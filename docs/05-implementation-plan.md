# 轻量实施计划

文档状态：已批准
版本：0.2
日期：2026-08-15

## 1. 当前策略

停止按卡片平台和正式商用系统继续扩张。后续只维护入口、面板、基础布局、便签和天气。

普通任务不再创建独立工作包文档，也不再为每个小改动同步多份完成流水账。

## 2. 阶段

### L0：仓库瘦身

目标：

- 清理可重建输出和无用缓存；
- 删除重复、已废弃的规划材料；
- 将 PRD、架构、测试和状态页改为轻量版本；
- 固化风险分级门禁。

退出条件：

- 当前锁文件需要的离线包仍可保留；
- 文档链接有效；
- 工作树没有意外生成物；
- 新策略由 ADR 记录。

### L1：可维护性收口

只做无行为扩张的结构整理：

1. 从 `MainWindow.xaml.cs` 提取布局持久化、便签列表和卡片订阅协调；便签删除/编辑与动效继续按状态页拆分；
2. 将 CoreBroker 命令路由拆为领域 handler；
3. 在保持调度行为不变的前提下拆分 Provider scheduler 内部职责；
4. 提取 PowerShell UIA 公共模块；
5. 统一构建和隔离验证输出路径。

每项单独提交，不进行“大爆炸”重写。

### L2：核心五项体验

只处理影响日常使用的问题：

- 入口打开/关闭可靠性；
- 面板启动、焦点和关闭；
- 布局拖动、保存和恢复；
- 便签保存、搜索和安全删除；
- 天气加载、位置设置和错误状态；
- 一个参考 Windows 11 x64 环境中的启动与后台占用。

不增加新卡片种类。

### L3：发布候选

只有用户明确准备发布时才执行：

- 干净环境和 CI；
- Debug/Release 全解决方案；
- 多显示器、DPI、无障碍和偏好矩阵；
- 性能和长稳；
- 安装、签名、许可证、Notice 和 SBOM。

L3 不是日常开发门禁。

## 3. 任务选择

优先级从高到低：

1. 数据丢失、安全或启动失败；
2. 核心五项的可复现缺陷；
3. 明显降低维护成本的局部重构；
4. 已测量的性能问题；
5. 视觉微调。

以下任务默认拒绝：

- 新卡片；
- 新插件或 Provider 平台；
- 云同步和账号；
- 为未来需求建立新抽象；
- 没有测量证据的性能重写；
- 只为增加测试数量而增加重复测试。

## 4. 变更规模

- 小修复：尽量限制在一个领域和少量文件。
- 跨 IPC 的功能：只修改实际需要的 Contract、Client、Handler 和领域服务。
- 若一个简单设置再次需要修改数十个文件，应先简化现有接线。
- 单文件已经过大时，不继续加入无关行为。

## 5. 验证

按 [08-testing-strategy.md](08-testing-strategy.md) 的 L0～L3 风险等级执行。

基本原则：

- 相关测试优先于全量测试；
- 一条真实、高价值流程优先于多条重复脚本；
- 发布矩阵只在发布候选执行；
- 无证据时不声称性能、兼容性或真实桌面行为已经完成。

## 6. 记录方式

- 当前任务和阻塞项写入状态页；
- 完成行为由 Git 提交和测试名称记录；
- 高成本决策使用 ADR；
- 已完成里程碑只在历史简表中保留一行；
- 不再维护逐工作包的累计路线。

## 7. 完成标准

一个任务完成时应满足：

- 没有扩大轻量核心范围；
- 相关行为通过匹配风险的验证；
- 没有引入新的重复基础设施；
- 生成输出已清理；
- 必要文档只更新一个权威位置；
- 提交目的单一。
