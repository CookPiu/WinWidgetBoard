# WinWidgetBoard UI、视觉与动效规范

文档状态：已批准基线

版本：1.0

日期：2026-08-24

> 本文是当前轻量核心版的 UI 权威规范，只覆盖任务栏入口、WorkspacePanel、基础布局、本地便签、天气与手动位置设置。计时器、待办、剪贴板、日历、插件、账号和云同步不是当前 UI 扩展目标。实现事实以本文和现有资源共同约束；出现偏差时，应先判断是实现回归还是确有必要修改规范，禁止直接复制局部常量形成第二套视觉系统。

## 1. 设计方向

产品视觉语言定为“静谧画布”：

- **内容优先**：边框、工具栏和状态提示不能挤占主要内容；
- **紧凑但不局促**：遵循 4 DIP 节奏，控件命中区不因视觉收缩而失去可用性；
- **一层主结构**：面板承载环境质感，卡片承载内容，避免卡片内继续堆叠有底色、有边框的容器；
- **系统原生**：优先使用 WinUI、Windows 语义色、系统字体、高对比度和减少动态效果设置；
- **直接稳定**：高频操作即时响应，拖动和缩放保持对象身份、位置与尺寸独立；
- **克制动效**：动效只解释状态、空间关系或操作反馈，不用于装饰和拖延。

所有新 UI 必须能回答三个问题：

1. 它是否让核心任务更快或更清楚？
2. 它是否可以复用现有 token、样式或组件结构？
3. 如果移除它的边框、底板或动效，信息是否仍然清晰？

无法回答时，不应加入界面。

## 3. 信息架构

```text
任务栏入口（嵌入任务栏条带的信息条）
├─ 信息文本（日期与时间；天气模式待定）
├─ 右键菜单（显示内容、快捷键、入口位置、左对齐回退）
├─ 全局快捷键（默认 Ctrl + Alt + B，开关面板）
└─ WorkspacePanel
   ├─ 单行头部
   │  ├─ 标题、日期和必要状态
   │  ├─ 便签搜索
   │  └─ 全局操作
   ├─ 卡片网格
   │  ├─ 本地便签（含便签切换器：搜索 → 列表 → 选中即收起）
   │  ├─ 天气
   │  └─ 已延期占位卡（只维护，不扩展）
   └─ 设置浮层（一处，按分类）
      ├─ 常规（开机自启）
      ├─ 天气（地点搜索 → 候选列表 → 只读经纬度）
      └─ 硬件监控（卡片与任务栏各一份指标列表）
```

强制约束：

- 搜索框不得独占一行；
- 单组按钮不得独占一行；
- 低频操作不得长期占据卡片正文空间；
- 状态提示只在加载、过期、离线、错误或空状态时出现；
- 临时结果层可以换行出现，但必须按需显示并可立即收起；
- 新入口、新设置分类和新卡片类型必须先通过产品范围决策。

### 3.1 任务栏入口

入口是嵌入任务栏条带的胶囊，不再是工作区内的方形按钮。开启硬件监控后它是**两枚胶囊**：
左边是主胶囊（指示器 + 时间或天气），右边是硬件胶囊，中间留一道间隙。两枚在同一个窗口里，
但互不重叠；间隙与两枚胶囊的圆角外侧一样穿透。

#### 尺度与结构

| 项目 | 值 |
| --- | --- |
| 高度 | 条带高度减去上下各 4 DIP，夹在 32～40 DIP，两枚胶囊等高 |
| 主胶囊宽度 | 随内容自适应，夹在 96～280 DIP，按 4 DIP 量化，另留一点余量 |
| 硬件胶囊宽度 | 随读数自适应，上限 440 DIP，按 4 DIP 量化，另留一点余量；**无下限**，没有读数时整枚不画 |
| 胶囊间隙 | 8 DIP |
| 圆角 | 短边的一半，形成胶囊 |
| 内边距 | 每枚胶囊左右各 12 DIP |
| 指示器 | 宽 4 DIP，与文本间距 8 DIP，静息高 4 DIP，面板打开时 16 DIP；只在主胶囊 |
| 天气图标 | 18 DIP 见方，与文本间距 8 DIP，仅天气模式出现 |
| 天气插画 | 尾部预留 26 DIP，仅在有天气读数时出现 |
| 硬件分段 | 每格为 12 DIP 图形 + 4 DIP 间距 + 数值，行高 15 DIP；两行为一列，列间 6 DIP + 1 DIP 细线 + 6 DIP |
| 字号 | 主胶囊 16 DIP；硬件分段 11 DIP，字体按 face 名指定（见下方「字体」） |

主胶囊内容自左向右为：12 DIP 内边距 → 指示器 → 8 DIP 间距 →〔天气图标 → 8 DIP 间距〕→ 文本
→〔天气插画 26 DIP〕→ 12 DIP 内边距。
指示器**始终占位**，只有高度和不透明度变化，因此状态切换不会引起重排；天气图标与天气插画只在
天气模式下占位，切换显示内容本来就会重新测量宽度。

**硬件监控是开关，不是第三种显示内容**：右键菜单里「显示内容」只管主胶囊（日期时间 / 天气），
硬件监控是独立的勾选项，因此天气与读数可以同时存在。两枚胶囊共用同一套悬停/按下/激活状态，
也共用同一个点击动作——它们是同一个窗口、同一个控件，分别高亮会暗示两件不同的事。

**面板还有一个全局快捷键**，默认 `Ctrl + Alt + B`，按一次开、再按一次关，与点击胶囊是同一个
动作。理由是入口本身够不着键盘：它是 `WS_EX_NOACTIVATE` 的覆盖窗口，永远不接收焦点，因此在这
个快捷键之前，打开面板**只能用鼠标**。

快捷键是入口自己的设置，和显示内容、入口位置一样存在 HKCU 而不是数据库里，也一样从右键菜单里
改——面板要先能被打开，才谈得上在面板里设置怎么打开它。菜单给的是四个预设而不是自由录制：入口
没有可以录入组合键的输入面，而全局快捷键会把这个组合从系统里其他所有程序手上拿走，因此预设一律
避开 Windows 保留的 Win 组合，也一律用字母——标点键随键盘布局移动，菜单会印出这块键盘打不出的
组合。参考机上 `Ctrl + Alt + Space` 是微软输入法的半角切换、`Ctrl + Alt + W` 被另一个程序占着，
两者作为预设时都注册成了「什么也没发生」。

**注册失败必须说出来。** 一个已被别人占用的组合注册不上，唯一的症状就是按下去没反应；菜单标题
因此在这种情况下写成「快捷键（被其他程序占用）」，而不是让用户自己猜。也**不会**自动换成另一个
预设：一个会自己搬家的快捷键比一个明说被占用的更难用。

插画必须自己占位，不能压在温度下面：入口只有 40 DIP 高，没有卡片右下角那样的空白可借。

天气模式显示**图标 + 温度**，不显示地区：地区是用户自己设定的，每分钟重复一遍只是在花掉入口的宽度。
图标即当前天气状况的表达，因此入口不含任何需要翻译的措辞。

图标由入口自己用圆、圆角矩形和一个多边形组合绘制，不使用图标字体——入口本来就在合成自己的
预乘位图，引入字体只会为这么小的一组图形增加一项可用性依赖。图标取值与 `conditionIconId`
一一对应（见 [API 契约](07-api-contracts.md)），未收录的标记画中性圆环，不猜相近天气。
图标使用与文本相同的颜色和不透明度：入口是系统表面，单色标记在任何任务栏底色上都保持可读。
识别当前天气靠的是这枚图标，不是插画。

#### 硬件监控分段

硬件胶囊把若干读数排成**两行**：第 1 个读数在上，第 2 个在下，构成第一列；第 3、4 个构成
第二列，依此类推。每格是「图形 + 数值」，同一列的两格左对齐、列宽取两格中较宽者；相邻两列之间
画一条跨越两行的 1 DIP 细线：到四列时，只靠间距已经不再读作分隔。细线的不透明度约为文字的
三成——一条和读数抢注意力的分隔线就不再是分隔线了。

分段字号（11 DIP）小于主胶囊（16 DIP），图形随之缩到 12 DIP。原因不是要塞下更多字，而是单行
主胶囊字号在 40 DIP 高的胶囊里既留下大片空白、又在第四个读数处用尽宽度；折成两行后同样宽度
可以容纳契约允许的全部八项，整枚读作一件密排仪表而不是一句话。

#### 历史走势

每个读数画在自己最近两分钟的历史之上：一层由旧到新的填充面积，不透明度约为文字的三成，
铺满该格所在的行。用**填充**而不是折线——这个尺寸下一条描边会和它前面的数字互相干扰，
而一块面积即使很矮也仍然读得出形状。

刻度由 Broker 给出（见 [API 契约](07-api-contracts.md)），入口只负责把 0..1 映射成高度：

- 有上限的指标（百分比、用量）按自身上限绘制，因此 24% 的 CPU 就画成矮矮一条，
  不会被拉伸到填满格子——各读数之间的高度可以横向比较；
- 速率没有上限，只能按窗口内峰值相对绘制，并设一个下限门槛，否则空闲网卡的背景流量会被
  放大成一片山峦。因此速率图的高度**不表示绝对量**，绝对量由它上面的数字负责；
- 本机读不到的指标不画任何图形，与「读数为 0」在视觉上必须可区分。

四条约束：

- **装不下的列整列省略**，不半截截断，也不留下上面有读数、下面空着的半列；被省略的列连同它
  左侧的细线一起消失。以半个图形收尾会被读成渲染故障，干净地结束不会，而卡片仍然显示全部配置项；
- 条带放不下两枚胶囊时**先丢硬件胶囊**，不丢入口本身：入口必须始终可达；
- 落单的读数（奇数个，或只配置了一项）居中于胶囊中线，不假装下面还有一格；
- 入口**不出现任何需要翻译的文字**：短标签（`CPU`、`MEM`、`GPU`、`VRAM`、`DISK`、`FAN`）
  在本产品发布的两种语言下写法相同，网络方向由箭头图形表达；
- 硬件图形与天气图形同源、同一套绘制原语，但**不画插画**：天气有天空，CPU 没有。

数值本身由 Broker 排好版后送来（见 [API 契约](07-api-contracts.md)），入口不做格式化。

#### 天气插画

有天气读数时，入口还画一层与卡片同源的平面插画：整枚胶囊铺一层天空色，尾部预留的 26 DIP 里
画一个当前天气的图形，越过收尾的圆头少许并被胶囊裁切。它与卡片是同一套东西——同一组
`WwbWeather*` 配色、同一批形状、同一个「天空 + 图形」结构——只是尺度按入口重排。

三条约束：

- 插画是装饰，不是状态：识别天气靠图标与温度，插画消失也不丢信息；
- `unknown` 与非天气模式**不画插画**，也不预留那 26 DIP——没有读数就不该借某种天气的颜色；
- 高对比度完全不画，与卡片一致（`WwbWeather*` 在该主题下全部为 `Transparent`）。

插画画在底色之上，而不是之下：压在中性底色下面时天空与图形都会被冲淡成一团灰。
这一点与卡片相同——卡片的插画也在卡片表面之上。

#### 颜色映射

入口是分层窗口，没有 XAML，也就没有 `ThemeResource`。因此面板的调色板在这里被映射成
最小且可核对的一组，**不允许**在此之外再引入颜色：

| 角色 | 来源 |
| --- | --- |
| 强调色（指示器、打开态染色） | `GetSysColor(COLOR_HIGHLIGHT)` |
| 中性底色 | 纯白或纯黑，由 `HKCU\...\Themes\Personalize\SystemUsesLightTheme` 决定（任务栏跟随的是这个值，不是应用主题） |
| 天气插画 | `WorkspaceVisualStyles.xaml` 的 `WwbWeather*` 主题字典，在入口侧按第 6.2 节的例外重述 |
| 高对比度 | 全部改用 `GetSysColor`，取消一切半透明，并恢复 1 DIP 系统边界 |

底色不透明度（深色条带 / 浅色条带）：静息 `0.10` / `0.07`，悬停 `0.20` / `0.15`，
按下 `0.26` / `0.21`，面板打开 `0.24` / `0.20`。浅色一侧的步长更大，因为深色叠加在浅色上
每单位 alpha 的感知对比明显更低。打开态在底色中混入 `0.85` 的强调色。

#### 质感

- 底色带自上而下 `0.22` 幅度的轻微渐变，只用于制造厚度，不作为装饰性渐变；
- 深色条带在胶囊上半沿加一道 1 DIP 的白色微光（`0.16`），到中线淡出，表达受光边缘；
- 除高对比度外不画描边——第 6.3 节的「不给每层容器描边」同样适用于入口。

#### 状态与动效

| 状态 | 表达 |
| --- | --- |
| 悬停 | 底色不透明度提高 |
| 按下 | 底色继续提高，胶囊与指示器整体缩放至 `0.97` |
| 面板打开 | 底色染上强调色，指示器由圆点**长成**竖条 |

- 状态不得只靠颜色区分：打开态的判据是指示器的**形状变化**；
- 三个通道各自是一条临界阻尼弹簧，角频率与面板本体的展开缩放通道相同（`15.4919`，见 9.3），
  使入口点亮与面板展开在同一条曲线上收敛，而不是两个可见的不同速度；
- 动画定时器只在状态迁移期间存在，收敛即销毁：静息入口没有任何定时器唤醒；
- 反向操作从当前显示值继续；
- `SPI_GETCLIENTAREAANIMATION` 为 `FALSE` 时改为约 150 ms 的淡入淡出，并因此自动去掉缩放。

### 3.2 天气卡片插画

天气卡片在内容之后叠一层随天气状况变化的平面插画，用来让卡片在一屏之内可被快速辨认，
而不是靠读温度数字。

- 构成是「一层天空底色 + 一到三个平面图形」，图形放在卡片**右下角的空白区**并溢出圆角；
  右上角归位置标签所有，把图形放到那里只会读成一团污渍；
- **卡片上任何一点最多叠两层半透明：天空一层，图形一层。** 图形画在同一个组里，不透明度由
  组承担（`WwbWeatherMotifOpacity`，深色 `0.18` / 浅色 `0.20`），组内各形状用**不透明**画刷，
  因此云挡住太阳的部分是遮挡而不是相加。让每个形状各自半透明会把每一处重叠变成比两者都亮的
  斑块——太阳会透过云显出来，两朵云之间会有一道缝；底色不透明度 `0.18`～`0.26`；
- 图形分两个色调（`WwbWeatherMotifBrush` / `WwbWeatherMotifStrongBrush`），前后关系靠色调而不是
  靠不透明度差；同色调的两个形状重叠会并成一个轮廓，那正是相邻两朵云必须分色调的原因；
- 正文始终是卡片上对比度最高的元素；
- 插画裁剪到卡片自身的圆角，不接收指针输入，也不带自动化名称——同样的事实已经由卡片文字表述；
- 一次只实例化选中的那一个背景（`WeatherBackdropTemplateSelector`），因为网格会在拖动时
  实例化和回收卡片表面；
- 毛毛雨与雨共用一张插画：卡片大小的图形本来就画不出两者的区别；
- 未收录的天气标记不画插画，而不是画一个相近的天气。

#### 约束

- 合成使用预乘 BGRA 位图与 `UpdateLayeredWindow`，圆角与文字都带真实逐像素 alpha；
  不使用色键透明，也不设置窗口区域——两者都会把抗锯齿边缘削回一位透明度；
- 文本一律按 **face 名**取字体，不向家族请求 `FW_SEMIBOLD`——GDI 的映射会向上取到 Bold 面，
  在这个尺寸下字腔被填满、读作毛糙；
- 字体用 Segoe UI Variable 的光学尺寸切分：主胶囊取 `Segoe UI Variable Text Semibold`，
  硬件分段取 `Segoe UI Variable Small Semibol`（GDI 家族名截断到 31 字符）。两者在同一 em 下
  的 x 高度和字距都大于 Segoe UI，这是胶囊在任务栏上读得清楚的主要原因。该家族随 Windows 11
  提供；缺失时整枚入口一起回落到 `Segoe UI Semibold`，不允许两枚胶囊各用一种字体；
- 蒙版用 ClearType 渲染但按三个子像素样本**取平均**当作灰度覆盖率——等于水平三倍采样，
  且因为最终只用一个颜色合成，不会出现彩色边缘；
- **宽度的滞回只能压制收缩，不能压制增长。** 内容一旦超出已预留的宽度必须立刻重排：
  胶囊放不下时不会截断，而是整列丢弃，实测会让最后一列（默认配置下正是网速）间歇性消失。
  收缩则要等空余累积到足够多才回收；每次重排都多留一点余量，让读数的小幅摆动不必再动窗口；
- 入口只在**胶囊本体**内接收输入，圆角外侧与其余区域穿透；
- 内容变化只重绘，不重排，除非重排是让内容装得下或回收明显空余所必需的。

### 3.3 设置浮层

**全部设置集中在同一处**，左侧分类栏一类一项，右侧是该分类的内容。用分类栏而不是把各段
纵向堆起来：每类设置都有一屏控件，堆叠会让硬件监控的两份指标列表离自己的标题一屏远。

第一类是**常规**，放应用自身而非某张卡片的设置，头部的设置按钮也落在这里；卡片的设置按钮仍各自
深链到自己的分类。目前它只有「开机自启」一项。

**常规没有提交区**，这是唯一一个没有保存按钮的分类。其余分类编辑的是 Broker 里带 revision 的
记录，需要一次提交，也可能报冲突；开机自启是请求系统加一个启动项，做成了或没做成，事后再点
「保存」无从谈起。开关下面那行状态说的是刚才那一下的结果。

开机自启的**唯一事实来源是系统自己**：状态读自启动文件夹里有没有那个快捷方式，打开就是把安装器
写好的开始菜单快捷方式复制过去，关闭就是删掉它。不另存一个开关位——用户在资源管理器里删掉那个
快捷方式就是关掉了这项设置，多存一份必然与系统打架。直接从构建输出运行的版本没有可复制的开始
菜单快捷方式，此时开关禁用并说明原因，而不是给一个按下去没有反应的开关。

卡片自己的设置按钮不再另开对话框，而是**深链**到该卡片的分类——入口不同、落点不同，打开的
是同一处，用户仍可在浮层内切到别的分类。

保存按分类各自进行，因此浮层的关闭按钮是「关闭」而不是「取消」：它不撤销已经保存的内容。

**本浮层内不使用星号列，宽度一律显式写出。** `ContentDialog` 内的内容按无界宽度测量，星号列会
把整个宽度交给第一个子元素、把 `Auto` 列排到裁剪之外；元素仍在自动化树里，但矩形为空、读作
offscreen，画面上只表现为「按钮不见了」。天气的搜索按钮和硬件监控的下移按钮都栽在这上面。
`MaxWidth` 只钳制结果、不改变测量，所以不够——容器给 `Width`，行内给具体列宽。

分类段分为**滚动的主体**与**固定的提交区**。提交区放该分类的输入、保存按钮和状态：分类内容比
任何本面板能容纳的对话框都高，保存按钮若只是排在最后就会滚出视野，与被裁掉没有区别。

按钮用 `WwbDialogButtonStyle` / `WwbPrimaryDialogButtonStyle`，**不要用 `WwbToolbarButtonStyle`
系列**——后者把字体设为 `Segoe Fluent Icons` 并把内边距归零，因为它们的内容是单个字形；用它渲染
文字会出来一串豆腐块。

**浮层用面板自己的材质与层次**：半透明底、面板圆角、分类栏与两个分段各坐在卡片/次级表面上，
列表带自身边界，好让被截断的那一行读作「可滚动」而不是「坏了」。浮层的外圆角由模板的
`OverlayCornerRadius` 画出，**不是**控件上的 `CornerRadius`——只设后者，浮层会保持系统的 8 DIP，
而它内部每一块表面都是面板的 16。标题同样按 `TitleTemplate` 降到面板标题的字号：一张盖在面板上
的设置纸不该比它盖住的东西喊得更响。

#### 天气

对话框的顺序就是用户的思路：**搜索地名 → 从候选中选择 → 保存**。

- 搜索框在提交时才发起请求，不做按键即搜；请求进行中显示不确定进度条；
- 候选行显示「名称」与其下一行的「一级行政区 · 国家」，用来区分同名地点；
  城市州（名称与行政区、国家相同）只显示一次，不重复自己的名字；
- 经纬度**只读展示**，标题写明「将保存的经纬度」：它是真正会发给天气服务的东西，
  藏起来会让这件事不可见，可编辑又会把用户重新推回抄坐标；
- 「没有匹配的地点」与「搜索暂时不可用」是两条不同的状态文案，不能合并；
- 位置名称仍可编辑：搜索结果给出的名称未必是用户想在卡片上看到的写法；
- 未搜索时列出**常用地点**，搜索后由结果列表取代——两份列表不同时出现，否则会在答案下方
  一屏处再放一组无关城市。常用地点是一份手写的便捷清单，不是地点数据库：ADR-0027 拒绝的是
  引入需署名、且仍会覆盖不到区县的第三方数据集，搜索仍然是能到达任意地点的机制。清单里的
  名称用地理编码返回的拉丁写法，好让预置项与搜索结果在同一列表里读起来一致。

#### 硬件监控

卡片与任务栏**各自一份列表**，每份列出全部指标：勾选决定是否显示，位置决定顺序，
下拉决定详细度。把未勾选项留在同一列表里，是为了让用户先把某项挪到想要的位置再打开它，
而不是打开后再一步步往上挪。

每处最多 8 项，超出时在对话框内就地提示，而不是等保存失败。

**网络来源**紧挨着两份指标列表，不单独成一类：它改变的是上传/下载两行的含义，读数和它的测量
对象不该隔一个分类。列表第一项恒为「全部网卡（合计）」——那是可配置之前的含义；其余来自 Broker
的实时枚举，与采样器同一套过滤条件，所以列表不会提供采样器会忽略的网卡。已保存但当前找不到的
网卡仍留在列表里（拔线、断 VPN），否则界面会显示「全部合计」而 Broker 手里还攥着那块网卡，
下一次保存就悄悄丢掉了用户从没改过的选择。

### 3.4 天气卡片

两段，按问题被问出来的顺序排：**现在如何 → 接下来如何**。旧版把体感、湿度、风速、观测时间
挤成同一权重的四行 caption 放在气温旁边，等于让观测时间和气温平起平坐。

- 首屏是一个数：气温用大号字，其下是条件字形加天气描述，再下面是**今日最高与最低**；
- 今日区间**在所有尺寸上都显示**，位置在条件之下、次要读数之上。实况回答「现在多少度」，
  它回答「今天还会怎样」，是唯一一对能改变读者接下来做什么的数；最高与最低各自带名称，
  否则屏幕阅读器只会连读两个数字。数据来自实况载荷而不是预报列表——预报列表从明天起算；
- **次要读数一律带名称**，横排三列、名称在上数值在下。`32.4 °C`、`87%`、`1.6 km/h` 三个裸数
  没有说哪个是体感哪个是湿度，其中第一个还会被读成第二个温度。横排也比三行竖排矮一半，
  差出来的正是 `L` 上第三天预报的那一行；
- 天气描述**按语言取字**。投影是 WinUI-free 的，所以它给出资源键而不是自己解析，由卡片用面板
  的资源加载器取；查不到的 WMO 码回落到英文描述而不是空行；
- 逐小时走势**横向滚动，不换行**：它是时间上的一条序列，换行出来的第二行会被读成第二天；
- 每日预报的最高与最低分列，三行才能对齐成两列，而不是三句参差不齐的话；
- 观测时间与来源署名合成**一行页脚**，署名不再是强调色链接：这张卡片讲的是一个温度，
  署名不该是上面最响的东西。观测时间格式化为时钟读数，provider 传的是本地 ISO 时间戳，
  原样显示等于让机器替用户读时间。

**内容按卡片尺寸渐进披露**，判据是**行数与列数，不是尺寸序**：

| 尺寸 | 格 | 显示 |
| --- | --- | --- |
| `S` | 1×1 | 地点 + 气温 + 天气 + 今日最高/最低 |
| `M` | 2×1 | 加次要读数 |
| `W` | 4×1 | 次要读数 + 逐小时**并排**在右半 |
| `L` | 2×2 | 次要读数 + 逐小时 + 三日预报（纵向堆叠）+ 页脚 |
| `XL` | 4×2 | 同上，预报并排在右半 |

**并排与堆叠是同一套模板的两个单元格，不是两份标记**：预报块的 `Grid.Row` / `Grid.Column` /
`Grid.ColumnSpan` 由 `CardSurfaceItem` 算出并绑定，所以树里只有一份逐小时列表、一个自动化 ID。
`W` 是四列一行——和 `M` 一样矮——把走势放进空着的右半是它唯一装得下的方式。

堆叠时预报**必须跨两列**。留在 `Auto` 列里它会被按无界宽度测量，而日行的最高气温在星号列里，
于是被排到卡片裁剪之外：星期和字形显示，两个温度不显示。这与设置浮层那条「不用星号列」是同一
个陷阱。

卡片高度是固定的网格行数，放不下的内容会被裁掉而不是滚动，所以在装不下的尺寸上显示走势，
得到的是一排被切掉字形和温度的时间——比不显示更糟。天气卡片默认尺寸因此由 `M` 提到 `L`，
理由与硬件监控卡片相同。**任何按尺寸披露的内容，在 `UpdatePlacement` 里必须重新发布**：
改尺寸只会触发 `Placement` 变更，否则卡片放大后要等到下一次快照才会长出走势。

条件字形是**一条几何路径**，不使用图标字体：卡片的插画本来就是用图元合成的，为八个形状引入字体
等于多一个可用性依赖。之所以是一条路径而不是一摞圆：字形取的是半透明的文本语义色，摞起来的话
每两个圆相交的地方都比云的其余部分深一号，18 DIP 上的一朵带三道缝的云读作噪点。单条路径在落笔
前先把自己的子路径并起来，所以子路径必须同向（圆一律顺时针、扫掠标志取 1），否则重叠处会被挖空。
云占上三分之二、降水记号占下三分之一——共用同一条带会让 18 DIP 的雨糊成一团黑。昼夜共用同一形状：这个尺寸下弦月和圆盘几乎是同一个记号，而昼夜之分由足够大的
插画承担。字形取**文本语义色**而非插画调色板：它陈述事实，因此在高对比度下必须仍然可见，
而插画按契约会整体透明。

### 3.5 便签卡片

**便签浏览属于便签卡片**，不在面板头部。头部位于所有卡片之上，包括与便签毫无关系的那些；
结果层一展开还会把整块板子往下推。搜索框、列表按钮和结果层现在都在卡片里，按需展开。

**选中一条便签即收起切换器**：挑选是浏览的终点。在头部时它只是浮在板子上方，代价为零；在卡片
里不收起，就会把用户刚要的那条便签挤到视野之外。

**便签可以弹出为独立窗口**，供临时使用：可调整大小、可切换「保持在最前」，与卡片共用同一条便签
和同一个编辑器。一次只有一个窗口——再点一次是把已有窗口带到前面，而不是开第二个：两个窗口编辑
同一条便签会互相争夺光标。窗口的默认尺寸按 DPI 换算，`AppWindow.Resize` 收的是物理像素，直接
传逻辑值在 200% 缩放下只有一半大。

窗口**用面板自己的表面搭起来**：Desktop Acrylic、同一层强调色薄雾、面板的头部条，正文坐在一张
卡片表面上。内容延伸进标题栏，所以那条头部就是面板的头部，而不是压在面板头部之上的系统标题栏。

- 「保持在最前」是窗口所处的**模式**，用图标切换按钮陈述，按下态即是答案；头部一行里放复选框
  会读成标题旁边的表单字段；
- **只有标题那一条是拖拽区**，不是整条头部：拖拽区会吞掉指针输入，而按钮就在同一行。标题文本
  关掉命中测试骑在上面，于是文字也能拖，而不是拖拽区上的一个洞；
- 右侧留出的空位宽度取自 `AppWindowTitleBar.RightInset` 并换算成 DIP。系统按钮的宽度随缩放变化，
  写死一个常数会在一块屏幕上把切换按钮压到最小化按钮底下、在另一块上空出一截。

**编辑器随卡片长高**，不设固定高度。正文原先写死 `148 DIP`，把卡片放大只会多出空白——这张卡片
存在的理由是那块可写区域，而放大买到的却是它周围的留白。

星号行在 `ScrollViewer` 里会被按无界高度测量并塌缩回内容高度，所以滚动内容必须先被告知撑满视口
（`MinHeight` 绑定到滚动器的 `ViewportHeight`），星号行才有真实高度可分。这与设置浮层里那条
「不用星号列」是同一个测量陷阱的两面。

### 3.6 硬件监控卡片

每项读数一行：名称在左、数值在右，下面按需要跟一条进度条和一行次要信息。

- **有明确上限的读数才画进度条**（占用率、已用/总量）。速率类不画：拿一个虚构的上限当满刻度，
  等于宣称一个这个读数并不具备的量程；
- 详细度决定行的丰满程度——仅数值 / 数值与进度条 / 再加次要信息；
- 读不到的项显示状态文字而非 0 或占位数字，进度条一并消失；
- 进度条使用语义色，不引入第二套调色板；本卡片没有天气那样的字面色例外。

刷新时**就地更新行**，不重建列表：卡片每两秒变一次数字，整表重绘会让每行的视觉每两秒重建一次。
这与第 4.3 节的稳定身份不变量是同一条规则。

## 4. 面板与响应式布局

### 4.1 面板几何

- 面板宽度目标为工作区宽度的 `46%`，逻辑宽度限制在 `680～960 DIP`；
- 面板高度目标为工作区高度的 `90%`，逻辑最小高度为 `560 DIP`；
- 面板距工作区边缘 `10 DIP`；
- 优先从 LauncherHost 所在角落展开；入口几何不可用时使用工作区左下角；
- 所有尺寸按当前显示器 DPI 换算，最终矩形不得越出工作区；
- 不以全屏或固定像素代替响应式计算。

### 4.2 卡片网格

| 项目 | 当前基线 |
| --- | ---: |
| 列数 | `2 / 4 / 6` |
| 列间距 | `8 DIP` |
| 行间距 | `8 DIP` |
| 基础行高 | `160 DIP` |
| 内容对齐 | 顶部开始 |
| 内容滚动 | 面板主体统一滚动 |

列数由可用宽度和已有布局合同决定。卡片跨度只能使用布局模型支持的值，不得通过负边距、绝对坐标或局部缩放伪造尺寸。

### 4.3 稳定身份不变量

布局编辑必须同时保持以下不变量：

- 每个卡片实例在同一编辑轮次内只有一个稳定 `InstanceId`；
- placement 或 order 变化只原地更新稳定的 `CardSurfaceItem`，不能为了刷新位置重排数据源对象；
- 只有成员增删才允许重建或重新绑定 ItemsRepeater 数据源；
- 拖动和缩放必须从当前已实现的 repeater 元素解析目标，不能依赖可能过期的根元素 `Tag`；
- 一个卡片的尺寸步进只基于该卡片当前尺寸，不得继承上一个操作对象的尺寸；
- 拖动、缩放、撤销和重做不得产生重复卡片或让其他卡片发生位移。

凡修改 `CardGridLayout`、`CardLayoutSurfaceViewModel`、ItemsRepeater 绑定、拖动或缩放代码，必须执行“同一编辑轮次下跨卡片拖动 + 缩放”的真实组合回归。

### 4.4 增删卡片

移除与添加是同一条编辑路径的两端，都只在编辑模式下出现：

- 添加入口是编辑模式工具栏里的一枚图标按钮，与撤销/重做同时显示、同时隐藏。它**不得常驻**：
  静息工具栏归内容所有，一枚只在编辑时有意义的按钮常驻就是第 2 节禁止的常驻 chrome；
- 选择器只列出当前不在面板上的内置卡片。内置实例是单例，同一身份不能出现两次——布局记录、
  Broker 订阅和便签编辑器都以这个身份为键；
- 全部卡片都在面板上时不弹出空对话框，直接在状态行说明；
- 添加进入与移动、缩放同一条撤销历史，并与其余改动一起在完成编辑时写入。新卡片落在布局末尾，
  由确定性首次适配决定实际位置，不指定像素坐标。

## 5. 密度与空间

### 5.1 4 DIP 节奏

| Token | 数值 | 典型用途 |
| --- | ---: | --- |
| `WwbSpace1` | `4` | 图标与标签、紧密工具组 |
| `WwbSpace2` | `8` | 网格间距、卡片内部行距 |
| `WwbSpace3` | `12` | 紧凑卡片内边距、主要区域间距 |
| `WwbSpace4` | `16` | 较大内容分组 |
| `WwbSpace5` | `20` | 少量强调留白 |
| `WwbSpace6` | `24` | 页面级分隔 |
| `WwbSpace8` | `32` | 控件命中基线或极少数大间距 |

已批准的组合值：

- 头部内边距：`12,8`；
- 主体内边距：`12,6,12,12`；
- 标准卡片内边距：`14`；
- 紧凑卡片内边距：`12`；
- 次级表面内边距：`8`；
- 工具栏内边距：`4`。

新增间距优先从表中选择。不得在同一组件中混用大量 `5/7/9/11/13/15` 等近似值制造不可维护的“视觉微调”。

### 5.2 空间预算

- 头部只保留一行常驻结构，标题区最大宽度受限，搜索使用剩余空间，全局按钮靠右；
- 卡片头部只容纳标题和最常用操作；
- 卡片正文是首要空间，辅助说明、重复标签和装饰性图标不得压缩正文；
- 便签默认态只常驻标题、正文、新建和“更多”；
- Markdown、复制、删除、恢复、重试等操作按模式或状态出现；
- 无内容时使用一句简短提示和一个下一步，不使用多层空状态卡。

## 6. 材质、颜色、边框与圆角

### 6.1 层级

1. 顶层面板使用 Desktop Acrylic 承载环境色；
2. 面板顶部可叠加系统强调色微光，当前不透明度为 `0.06`；
3. 卡片使用较实的系统语义表面，保证文字稳定可读；
4. 浮层可使用 In-App Acrylic，但不能与多层半透明卡片叠加；
5. ThemeShadow 只表达浮起或层级，不作为常驻分隔线。

### 6.2 颜色

- 只使用 `ThemeResource` 和 Windows 语义色表达文字、表面、强调、危险及禁用状态；
- 不为普通正文、图标或按钮写死 RGB/十六进制颜色；
- **唯一例外是天气插画配色**：没有任何 Windows 语义色的含义是「阴天的天空」。
  该配色集中定义在 `WorkspaceVisualStyles.xaml` 的主题字典里，键名一律以 `WwbWeather` 开头，
  页面只引用键、永远不自己写颜色；高对比度把其中每一个都改为 `Transparent`。
  `UT-UI-002` 会断言这两条：字面颜色只能出现在 `WwbWeather*` 画刷上，且必须在高对比度里被清零；
  任务栏入口画同一套插画，但它是分层窗口、没有 `ThemeResource` 可查，只能像第 3.1 节的
  4 DIP 节奏那样把这组值重述一遍。**`WorkspaceVisualStyles.xaml` 仍是权威**：入口侧的副本
  取其 Default 字典对应深色条带、Light 字典对应浅色条带，高对比度不画；改配色要两边一起改；
- 强调色只用于焦点、选中、主要动作和少量环境微光；
- 危险色只用于真实破坏性动作或失败状态；
- 不能只靠颜色传达状态，必须同时有文字、图标、形状或自动化名称。

### 6.3 边框

- 普通主题的面板、头部、卡片和次级表面默认边框为 `0`；
- 高对比度主题恢复系统 `1 DIP` 边界；
- 浮层边框为 `1 DIP`；
- 禁止为了“精致感”给每一层容器都加描边；
- 分组优先使用间距、字号、字重、底色差和对齐，不优先使用线框。

### 6.4 圆角

| Token | 数值 | 用途 |
| --- | ---: | --- |
| `WwbPanelCornerRadius` | `16` | 顶层面板 |
| `WwbCardCornerRadius` | `12` | 卡片 |
| `WwbControlCornerRadius` | `7` | 输入、工具条、次级表面 |
| `WwbSmallCornerRadius` | `6` | 小按钮、拖动柄、骨架块 |

同一层级不得随意混用不同圆角。

## 7. 字体与控件尺度

使用 Windows 默认 UI 字体，不为普通界面引入品牌字体。

| 语义 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 面板标题 | `16 / 22` | SemiBold |
| 面板元信息 | `11 / 16` | Regular |
| 面板上下文 | `10 / 14` | Regular |
| 卡片标题 | `13 / 18` | SemiBold |
| 卡片正文 | `12 / 17` | Regular |
| 卡片说明 | `11 / 16` | Regular |
| 天气温度 | `28 / 32` | SemiBold |
| 便签标题输入 | `14` | SemiBold |
| 便签正文输入 | `13` | Regular |

控件基线：

- 头部图标按钮：`32 × 32 DIP`，图标光学尺寸约 `14 DIP`；
- 卡片图标按钮：`28 × 28 DIP`；
- 卡片常规动作：最小高度 `32 DIP`；
- 便签低频工具：最小高度 `28 DIP`；
- 搜索框：最小高度 `32 DIP`，字号 `13`；
- 拖动柄：最小命中区 `32 × 32 DIP`。

文字层级最多使用三档同时出现。不能通过不断放大标题来制造层级，应先减少周围噪声。

## 8. 组件结构模板

模板规定结构和职责，不复制一套脱离资源字典的硬编码样式。

### 8.1 面板壳层

```text
PanelRoot (Desktop Acrylic + WwbPanelRootStyle)
├─ AccentWash（高对比度自动禁用）
├─ HeaderSurface (WwbHeaderSurfaceStyle)
│  └─ Title/Meta | Search | GlobalCommands
├─ TransientSurface（默认 Collapsed）
└─ ScrollViewer
   └─ ItemsRepeater + CardGridLayout
```

### 8.2 卡片

```text
CardSurface (WwbCardSurfaceStyle, MinHeight=160)
└─ Grid (RowSpacing=8)
   ├─ Header
   │  ├─ Title
   │  └─ PrimaryAction / Overflow
   ├─ PrimaryContent
   └─ ConditionalStatusOrEditControls
```

规则：

- 卡片根元素使用统一表面样式、圆角和阴影策略；
- 主内容只保留一个主要视觉焦点；
- 常用动作直接显示，低频动作进入 Overflow；
- 状态区与编辑工具只在需要时进入视觉树；
- 不在卡片内部再套一个“完整小卡片”；
- 输入控件有明确字段语义时可保留控件边界；便签正文等沉浸式编辑区优先无嵌套描边；
- 当前产品范围不允许以此模板为由扩展新卡片类型。

### 8.3 运行状态

| 状态 | 表现 | 允许操作 |
| --- | --- | --- |
| Loading | 紧凑骨架或短提示 | 关闭、取消（若支持） |
| Ready | 不显示额外状态层 | 正常操作 |
| Stale | 保留最近内容并给出更新时间 | 手动重试 |
| Offline | 保留缓存内容并说明离线 | 手动重试 |
| Error | 简明原因和可执行下一步 | 重试或打开相关设置 |
| Empty | 一句说明和一个主要动作 | 创建或配置 |

状态层不得覆盖已有可用内容，也不得用 Ready 标签长期占位。

## 9. 动效规范

### 9.1 是否需要动效

| 场景 | 处理 |
| --- | --- |
| 高频点击、输入、拖动、缩放 | 即时反馈，不增加等待 |
| 面板出现/退出 | 解释与入口的空间关系 |
| 浮层、搜索结果、预览切换 | 短透明度和轻缩放过渡 |
| 布局重排 | 仅在不破坏 1:1 拖动和稳定身份时采用 |
| 长时间装饰、循环呼吸、颜色流动 | 禁止 |

### 9.2 参数与实现

- 渐进浮层进入：`180ms`，退出：`125ms`；
- 减少动态效果模式：`150ms` 淡化，不做位移和缩放；
- 浮层进入缩放从 `0.985` 到 `1`，退出目标不低于 `0.99`；
- 拖动浮起比例为 `1.01`，只辅助表达抓取，不改变布局测量；
- 按压反馈可使用 `0.96～0.98`，释放后立即恢复；
- 进入使用 ease-out，屏幕内移动使用 ease-in-out，颜色和悬停使用短 ease；不使用让操作初段迟钝的 ease-in；
- 优先只动画 `Opacity`、`Scale`、`Translation` 等合成层属性；
- 不动画 `Width`、`Height`、`Margin` 等会持续触发布局的属性；
- 面板开合、卡片折页和拖动回弹使用 `CompositionTarget.Rendering` 跟随当前 XAML 合成目标；
  不用固定 `16 ms` 定时器模拟 60 Hz，弹簧按 `Stopwatch` 实际帧间隔推进；
- 不使用 `transition all`、无因弹跳、长弹簧尾巴或无法中断的故事板；
- 反向操作必须从当前显示值继续，不能先跳回起点。

上述时长与缩放值针对渐进浮层、按压和拖动反馈；面板展开与收起不用单一时长，参数见 9.3。

任何新增动效都要在 UI 变更模板中填写“目的、频率、时长、属性、可中断性、减少动态效果降级”。没有明确目的时选择不动画。

### 9.3 面板展开与收起

面板底板始终保持最终位置，不再整体平移或缩放。开合由两层组成：

1. 原生窗口材质只做临界阻尼透明度变化，展开角频率 `25.5`、收起 `22.0`；收起不得慢于展开——两者收敛时长之比有单元测试兜底；
2. 当前已实现的每张卡片由**卡片自身的 `RenderTransform`** 驱动，朝任务栏胶囊方向沿独立二次曲线路径折起或展开，最终精确回到恒等值。

卡片通道以稳定 `InstanceId` 为身份，数量、顺序和尺寸均由当前已实现元素实时解析；会话已建立时重新准备必须按调用方给出的卡片顺序返回 ID，返回字典序会打乱逐卡片交错；新增或重排卡片不需要新增动效分支。第一张到最后一张的展开角频率在 `17.6 → 13.2` 之间按当前卡片数量归一化，较确认预览整体略慢；关闭使用反向排序的 `17.2 → 21.6`，后到卡片先折回。

折页的几何写在**卡片自身的合成视觉**上（`ElementCompositionPreview.GetElementVisual`），不写
`RenderTransform`。参考机实测：逐帧对 6 张卡片写 `CompositeTransform`，展开均值 `12.19 ms`、
收起 `15.69 ms`（165 Hz 的预算是 `6.06 ms`）；同一段动效只写透明度时是 `5.98 / 5.94 ms`；改到
合成视觉后是 `6.09 / 6.27 ms`。位图缓存对此**毫无作用**（`12.20 / 16.22 ms`），因此一并移除——
它当初是按「避免逐帧重栅格化」的假设加的，而该假设不成立。

位移必须写 `UIElement.Translation`，**绝不能写视觉的 `Offset`**：`Offset` 就是 XAML 布局给元素
定的位置，写它是替换而不是叠加，复位时置零会把每张卡片摞到父容器左上角。`Translation` 才是叠加
在布局之上的通道。

代价是明确且有界的：合成变换不在 XAML 命中链上，折页期间指针命中的是卡片**排布位置**而非绘制
位置。这在一段动效的时长内可以接受，且**仅限于这段时长**——落地必须回到精确恒等值，这正是它
不会变成持久性「渲染与输入不一致」的原因。

**禁止把活动卡片的 visual 交给合成层做源。** `RedirectVisual` 与 `CompositionVisualSurface` 都经实测会把该子树的 XAML 命中几何整体下移一个网格行，且会话结束后不恢复——面板排布与绘制都正确，指针输入却落在下一行。元素级合成变换（`Scale` / `Rotation` / `RotationAxis` / `CenterPoint`）在这里也不可用：卡片已有 `RenderTransform` 占用同一变换槽，写入直接抛 `UnauthorizedAccessException`（只有 `Opacity` 和 `Translation` 可写）。

因此折页只写卡片自己的 `CompositeTransform`。这不是退让：`RenderTransform` 属于 XAML 命中链，渲染与命中按契约必然一致，动画中途也对得上。代价是卡片被内容 `ScrollViewer` 裁剪，不能飞出面板。

首次展开必须等待 `RootGrid` Loaded 且当前可见卡片完成实现后再解析路径。折页期间给卡片挂 `CacheMode = BitmapCache`、结束时清回 `null`：`RenderTransform` 的缩放会让 XAML 每帧按新比例重新栅格化卡片内容，位图缓存改为变换同一张纹理，且不影响命中测试。

收敛阈值按感知取值：进度驱动不透明度，因此以一个 8 位 alpha 台阶（`0.004`）为界，不追解析尾巴——多出来的收敛时间只会让帧循环和收起后的窗口隐藏空转。

帧源由当前窗口所在显示器的 XAML 合成目标决定，自动适配 60 / 120 / 144 / 165 Hz 等刷新率；
切换显示器不缓存或硬编码刷新率。窗口位置只在几何应用时设置，不在每个动效帧重复调用 `SetWindowPos`。

翻转轴由“胶囊中心 → 卡片目标中心”的单位向量实时计算，铰点取“卡片中心 → 胶囊中心”射线与卡片边界的交点；卡片数量、顺序、尺寸或响应式列数变化后仍按当前几何重新解析，禁止所有卡片共用左下角支点或一组固定欧拉旋转。

行程保留胶囊方位但**限制长度**（`MaximumTravel = 110 DIP`）：胶囊锚点在面板之外，而卡片受 `ScrollViewer` 裁剪，跑满全程会有大半不可见，收尾归位读成一次跳变。

绕平面内轴的三维翻转在只有二维变换时用**沿轴垂直方向的压缩**近似，权重取轴分量的**平方**（单位向量满足 `ax² + ay² = 1`，因此折叠角归零时必然收敛到统一缩放）。用绝对值加权会在对角轴上求和到 `1.414`，让每张卡片全程放大 41% 并在末帧跳回——这条由单元测试守住。

运动中反向只改变弹簧目标，保留当前进度与速度；落地时位移、旋转和比例精确回到恒等值，不替换 `CardSurfaceItem`，不影响拖动、缩放、命中测试或 UIA 身份。元素回收（`Unregister`）时同样必须复位，否则回收后的元素会带着半截折页复用。

减少动态效果时禁用所有卡片路径、旋转和缩放，只保留约 `180 ms` 的整体材质淡化。`180 ms` 是**总时长**，不是指数衰减的时间常数：按 `exp(-t/0.18)` 驱动需要约 5.5 个时间常数（近 1 秒）才越过收敛阈值，会让无障碍路径反而比完整动效更慢，并把驻留隐藏一起拖住。反向时按剩余距离缩放时长，从当前显示值继续。高对比度保留空间运动。

## 10. 输入、焦点与无障碍

- 所有图标按钮必须有本地化工具提示、可读自动化名称和稳定唯一的 `AutomationId`；
- Tab 顺序遵循视觉顺序，浮层打开后焦点进入浮层，关闭后返回触发控件；
- `Esc` 优先取消当前拖动或编辑，其次关闭浮层，最后关闭面板；
- 拖动不能从 TextBox、Button、ScrollViewer 等交互控件误触发；
- 不能只提供拖动路径；布局编辑要保留可发现的缩放、增删、撤销和重做；
- 高对比度下使用系统色和 `1 DIP` 必要边界；
- 减少动态效果下保留状态变化和焦点反馈，只移除空间位移与缩放；
- 200% DPI 等缩放下，逻辑命中尺寸不变，不能用物理像素硬编码；
- 截断文本必须有可访问全量内容或替代说明。

## 11. UI 变更流程

每次可见 UI 变更开工前：

1. 阅读本文，并复制或引用 `docs/templates/ui-change-template.md` 作为工作检查表；
2. 固定参考环境：主题、DPI、窗口尺寸、语言、数据状态和基线提交；
3. 保存修改前截图或可复现描述；
4. 使用下表评审，不接受只有“更好看”的结论；
5. 优先修改集中 token、Style 或组件结构，再考虑页面局部值；
6. 按风险等级执行静态、构建和真实桌面流程；
7. 保存修改后同条件截图及交互证据。

UI 评审必须使用：

| Before | After | Why |
| --- | --- | --- |
| 当前可观察问题和证据 | 具体变化及数值 | 对内容空间、层级、可用性或一致性的影响 |

普通修复默认不提交一份已填写模板副本；设计决策、截图和验证结果可记录在任务、PR 或提交说明中。只有跨多轮、高风险或需要长期追踪的 UI 改造才单独保存记录。

## 12. 验收门禁

### 12.1 静态门禁

- 没有无理由的新颜色、间距、字号、圆角或阴影；
- 没有搜索、按钮或状态独占常驻整行；
- 没有新增嵌套边框和重复底板；
- 所有图标操作具备工具提示、自动化名称和唯一 AutomationId；
- XAML、资源键和本地化引用可解析；
- `git diff --check` 通过。

### 12.2 L2 真实桌面门禁

UI、布局、动效或进程交互变更至少验证：

- 受影响可执行文件的 Release 构建或 smoke；
- 一条直接覆盖本次风险的真实鼠标或键盘流程；
- 与参考条件一致的修改后截图；
- 常用操作无新增等待和误触；
- 涉及布局编辑时，跨卡片拖动 + 缩放组合不串尺寸、不丢位置、不复制卡片；
- 涉及动效时，快速反向操作不中断逻辑状态，减少动态效果有合理降级；
- 涉及主题与边界时，至少检查普通主题，并按风险决定是否增加深色、高对比度或 DPI 检查。

单元测试、进程正常退出或静态截图均不能单独替代真实交互证据。

## 13. 禁止项

- 注入或修改 Explorer；
- 以更多常驻工具栏换取“功能完整”；
- 把搜索、按钮组或说明文字拆成独立常驻行；
- 为每层容器增加背景、边框、圆角和阴影；
- 用任意硬编码颜色绕过系统主题；
- 用缩小命中区换取表面紧凑；
- 在拖动中加入破坏指针 1:1 投影的通用重排动画；
- 用新动画掩盖状态跳变、身份错配或数据刷新问题；
- 扩展延期卡片、插件、账号、云同步或复杂设置体系；
- 未固定参考环境就宣称视觉或性能改善。
