# 风险分级测试策略

文档状态：已批准
版本：0.2
日期：2026-08-15

## 1. 目标

测试用于证明本次修改的主要风险得到控制，而不是让每个小提交重复执行正式发布矩阵。

核心原则：

- 相关测试优先；
- 真实交互只覆盖自动测试无法证明的边界；
- 不以测试数量代替风险判断；
- 不重复复制 UIA 基础设施；
- 发布门禁与日常开发分离。

## 2. 风险等级

### L0：文档和无行为配置

适用：

- Markdown；
- 注释；
- 不改变构建结果的元数据；
- 清理被忽略的生成物。

验证：

```powershell
git diff --check
```

再运行文档链接或结构检查。不构建应用。

### L1：纯逻辑

适用：

- 布局纯函数；
- ViewModel；
- DTO 映射；
- 格式化；
- 无 I/O 的调度策略。

验证：

- 相关单元测试；
- 必要时构建受影响项目的 Release 配置。

无需自动运行全部 UIA、LauncherHost 和双配置矩阵。

### L2：边界行为

适用：

- XAML 或窗口交互；
- Named Pipe；
- SQLite；
- Provider 网络；
- 进程启动和重连；
- 任务栏命中与穿透。

验证：

1. 相关单元或集成测试；
2. 受影响可执行文件的 Release build/smoke；
3. 一条针对本次风险的真实桌面流程。

例如天气位置设置只需要证明保存、重启读取和天气刷新，不需要同时重跑所有便签与拖动脚本。

### L3：发布候选

仅在用户明确准备发布时执行：

- 干净 restore；
- 完整解决方案 Debug/Release x64；
- 全量测试；
- LauncherHost、CoreBroker、WorkspacePanel smoke；
- 多显示器和 100%～200% DPI；
- 高对比度、减少动态效果、文本缩放和键盘流程；
- 启动、后台 CPU/工作集、GPU/VSync 和长稳；
- 数据库备份恢复；
- 安装、更新、签名和许可证检查。

## 3. 当前核心测试面

| 领域 | 自动测试 | 真实验证触发条件 |
| --- | --- | --- |
| Launcher | 几何、输入状态、启动交接 | 改窗口、命中、定位或进程交接 |
| Panel | 启动上下文、关闭策略、动效状态 | 改 XAML、焦点、关闭或窗口行为 |
| Layout | 排布、投影、持久化、历史 | 改拖动、ItemsRepeater 或视觉落位 |
| Notes | repository、IPC、ViewModel | 改输入、保存、导航或删除 UI |
| Weather | Provider、调度、设置、IPC | 改 HTTP、位置、状态或天气 UI |

延期卡片不再作为新增验收范围。已有测试可继续作为回归资产，但不要求每次全部运行。

## 4. 单元与集成测试

- 测试名称应说明行为，不要求为每一条内部实现分支创建独立编号。
- 修复缺陷先增加最小回归或保存清晰复现步骤。
- 不为简单属性访问、框架行为或同一边界的重复组合增加低价值测试。
- IPC、revision、迁移、超时、取消和背压仍属于高价值边界。
- 测试应使用 fake clock、临时数据库和可取消依赖，避免真实等待。

## 5. UI Automation

UIA 只证明：

- 元素真实存在且可达；
- 点击、输入、拖动和对话框路径可执行；
- 进程和数据隔离正确；
- 关键状态可以从真实 UI 观察。

规则：

- 公共窗口查找、元素查找、点击、输入、滚动、进程启动和清理函数应提取到共享 PowerShell 模块；
- 新脚本不得复制整套 helper；
- 一条完整核心旅程优先于多条高度重叠脚本；
- UIA 通过不等于性能、DPI 或屏幕阅读器验证通过。

## 6. 真实桌面边界

以下行为不能只靠单元测试：

- 任务栏入口覆盖和鼠标穿透；
- 面板前台、失焦和模态保护；
- Pointer capture 与真实拖动；
- WinUI XAML 初始化；
- Provider 到 UI 的真实进程链路。

只有修改对应边界时才重跑相关流程。

## 7. 验收隔离

写入型验收必须：

- 使用 `--acceptance-test`；
- 使用新 GUID `--test-instance-id`；
- 数据目录是系统临时目录的严格子目录；
- 只终止脚本拥有的子进程；
- 不访问或修改生产数据库；
- 结束后删除临时目录。

不允许为了测试改变生产单实例和默认数据路径。

## 8. 性能

只有提供以下信息时才可写入性能结论：

- 设备和 Windows 构建；
- Release 构建；
- 是否附加调试器；
- 测量时长和场景；
- 工具和指标；
- 原始数据或摘要。

日常提交不要求跑性能矩阵。只有出现已测量回退或进入 L3 时执行。

## 9. 构建输出

- 标准输出可以位于 `artifacts/`；
- 进程锁导致需要隔离输出时使用 `%TEMP%`；
- 不保留多个 `final`、`retry`、`order-fix` 构建副本；
- 测试结束后清理可重建输出；
- NuGet 缓存只保留锁文件需要的版本；
- 清理前确认目标是仓库内生成目录或系统临时目录。

## 10. 提交前最小检查

按风险等级选择，不机械叠加：

```powershell
git diff --check
dotnet test .\tests\UnitTests\WinWidgetBoard.UnitTests.csproj -c Release --filter "<相关测试>"
dotnet build .\src\<受影响项目>\<项目>.csproj -c Release
```

若修改 UI/IPC/数据库，再增加对应 smoke 或一条真实流程。
