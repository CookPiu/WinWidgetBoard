# M2.4.2 NTE-001 便签保存失败后的显式重试

状态：已完成代码与自动测试；真实桌面故障恢复回归待完成
关联需求：NTE-001、NFR-REL-002
关联规范：便签保存状态与错误恢复规范
关联 ADR：ADR-0011、ADR-0013

## 目标

在便签自动保存失败后提供明确的“重试保存”入口。重试必须复用当前内存草稿，不能丢失用户输入，也不能引入无界后台自动重试。

## 实现范围

- `NoteEditorViewModel` 暴露 `CanRetrySave` 和 `RetrySaveAsync`；
- 只有保存错误、草稿未落盘且没有进行中保存任务时启用重试；
- 重试跳过 debounce，但仍经过统一的保存并发门和 revision token；
- 重试成功后清除未保存状态，连续失败时继续保留草稿和重试入口；
- WorkspacePanel 增加双语按钮、AutomationProperties 名称和成功/失败状态提示；
- 不做无界自动重试，不改变 CoreBroker、SQLite、revision 冲突或剪贴板持久化策略。

## 不在本工作包内

- 多便签搜索结果和便签列表；
- revision 冲突解决器或远端合并 UI；
- Markdown 渲染和编辑工具栏；
- 删除、完整撤销和恢复历史；
- Windows 剪贴板历史卡片。

## 真实桌面验证

在可交互 Windows 桌面中启动当前 `x64\Release` 面板，制造一次便签保存传输失败，确认正文仍在、状态提示明确且“重试保存”可操作；恢复 Broker 后点击重试，确认状态变为已保存并在重开面板后保留内容。该验证需要真实跨进程故障恢复，不由单元测试替代。
