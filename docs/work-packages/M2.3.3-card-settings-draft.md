# M2.3.3 卡片设置草稿与取消恢复

状态：已完成代码、自动测试和构建门禁

关联需求：CRD-004、SET-003

关联 ADR：ADR-0002、ADR-0003（本工作包不改变进程边界、IPC 或持久化）

## 目标

在 WorkspacePanel Runtime 内提供 UI 无关的卡片设置草稿契约：从不可变实例设置
快照开始，允许声明式 setting ID 的受限 set/remove；视觉设置可发出实时预览，取消
时按首次触碰顺序的逆序恢复；账号解绑、数据删除等 CommitOnly 设置不进入 preview。

## 实现范围

- `CardSettingsSnapshot` 深拷贝顶层 JSON object，保留未知字段，带 instance/card type、
  schema version 和 revision；设置 JSON 遵循 64 KiB/instance 上限。
- `CardSettingDefinition`/`CardSettingsSchema` 校验稳定 ID、重复 ID、JSON value kind、
  可选 setting validator 和 `PreviewSafe`/`CommitOnly` 策略。
- `CardSettingsDraft` 使用状态锁保护 Active/Committed/Cancelled、版本和候选 settings；
  外部 validator 与 preview sink 均不在状态锁内执行。
- `previewSink` 是受信、同步、本地回调，契约要求其不抛异常。若 Set/Remove 派发时
  sink 抛出，异常会向调用方传播，但草稿已保留新值、版本递增且仍为 Active；调用方
  应取消或丢弃并重开会话，不应通过再次提交同值来重试派发。Cancel 的 Restore sink
  调用则继续执行并在 `Failures` 中报告。
- PreviewSafe set/remove 生成不可变 change；Cancel 对每个实际 preview 过的 setting
  仅发出一次 Restore，并以 `CardSettingsPreviewRestoreFailure` 关联 setting 与异常，
  即使某个 handler 失败仍继续其余恢复。
- `BuildCommitRequest` 只生成带 session、draft version、instance、expected revision
  和完整 settings 的不可变请求；后续编辑使旧请求失效。`AcceptCommit` 仅接受当前请求
  和 expected revision + 1，成功后返回新快照并结束草稿，不执行数据库或 IPC。
- `_publishGate` 只串行 preview 的实际派发顺序；不会保护可观察草稿状态，所有外部
  回调都在 `_gate` 释放后执行。
