# M2.2.8 LYT-006 卡片布局持久化

状态：已完成代码接入和首轮缺陷修复；便携 SDK 下 Debug/Release 94/94 测试、WorkspacePanel/CoreBroker 构建通过，真实重启验收待用户确认
关联需求：LYT-006、DAT-001、NFR-REL-002
关联 ADR：ADR-0003、ADR-0005

## 缺陷表现

M2.2.6/M2.2.7 的拖动只能修改 WorkspacePanel 当前进程内的布局快照。点击“完成”后没有调用 CoreBroker，关闭或重启面板会按默认卡片顺序重新排布。

## 本次交付

- 新增 `layout.get`、`layout.save` 契约和 WorkspacePanel 高层客户端；
- CoreBroker 使用现有 SQLite `layouts`、`layout_items` 和 `card_instances` 表保存布局；
- 保存请求使用 `clientOperationId` 有界幂等缓存和 `expectedRevision` 冲突保护；
- WorkspacePanel 启动后加载 `primary-default` 布局，完成编辑时一次性保存，不在每帧拖动时写数据库；
- 拖动提交后按实际网格位置更新卡片稳定顺序，使保存的顺序和 preferred column 能在重启后重新排布；
- CoreBroker 不可用或保存失败时保留当前编辑状态，并显示可见错误，不伪称保存成功。

## 首轮验收缺陷修复

- 保存链路将握手失败等 `InvalidOperationException` 转换为可见的保存失败状态，避免“完成”按钮无反馈；保存期间显示“正在保存”并暂时阻止新的布局修改。
- 拖放提交不再直接重排运行时卡片集合。ItemsRepeater 保持卡片实例顺序稳定，只有保存时才按实际网格行列生成逻辑顺序，避免卡片因集合重建而互换视觉位置。
- 编辑取消快照和尺寸/移除操作统一使用当前网格顺序，避免拖放后继续编辑时误操作其他卡片。
- 保存成功和失败后的按钮状态切换统一通过 UI Dispatcher 完成；保存成功恢复“编辑布局”，失败保持“完成编辑”以便继续修改。
- 卡片回弹动画结束、取消编辑和重新进入编辑时同步清零拖动控制器偏移，避免第二轮拖动叠加上一轮的旧偏移。

## 当前限制

- 当前演示面板使用 `primary` 显示器标识；真实多显示器 ID 接入属于后续显示矩阵工作；
- 仍未实现 20 步撤销/重做、实时让位预览和其他卡片领域 CRUD；
- 真实 Windows 桌面关闭/重启 CoreBroker、重开面板的人工验收待完成。
