# M2.0.1 版本化 IPC Envelope 与校验

状态：Contracts 实现与契约测试已完成；命名管道传输、ACL、握手和 CoreBroker 待后续工作包
关联需求：G-006、SYS-001、NFR-REL-001
关联规范：接口与数据契约第 1、2、14、16、17、18 节
关联 ADR：ADR-0002、ADR-0007

## 目标

在真正启动 CoreBroker 和 Named Pipe 之前，先固定所有进程共享的最小消息边界：

- `request`、`response`、`event` 使用同一 Envelope；
- 属性名使用 camelCase，时间使用 UTC，标识使用 UUID；
- response 必须带请求的 `correlationId`；
- 主版本不兼容时拒绝，未来同主版本 minor 可保留未知可选字段；
- 空消息、畸形 JSON、非对象 payload、无效错误字段和超过 1MiB 的消息被拒绝；
- JSON Schema、C# 类型、Envelope 编码器、4 字节 little-endian 长度帧和契约测试保持同一字段边界。

## 本次允许修改

- `src/Contracts/Protocol/`；

- Contracts 引用和 UnitTests；
- 实施计划、实施状态、测试说明和本工作包文档。

## 实现边界

- 不创建 CoreBroker 进程；
- 不创建 Named Pipe、ACL、会话令牌、握手、心跳、超时或重连实现；
- 不把 JSON Schema 的 `format` 校验误称为传输安全；
- 不记录、打印或回显潜在的 token、payload 正文或错误详情；
- 1MiB 校验发生在 JSON 反序列化前，避免先按不可信长度分配对象。
- 长度帧读取必须处理部分读，且在分配 payload 缓冲区前检查长度。
