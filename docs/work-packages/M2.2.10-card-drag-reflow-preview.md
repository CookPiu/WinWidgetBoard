# M2.2.10 LYT-003/004/005 卡片拖动入口与实时让位修复

状态：已完成代码、自动验证和当前单屏四卡真实回归；完整显示与性能矩阵待完成
关联需求：LYT-003、LYT-004、LYT-005
关联 ADR：ADR-0003

## 缺陷

- 便签内容表面接入了拖动事件，计时器、待办和本地日历只有底部拖动柄接入，四种模板的命中契约不一致；
- 落点投影把其他卡片视为固定障碍，拖到已占用单元格时只能回退到远处空位，不能按需求让位；
- 指针移动期间虽计算预览 placement，但结果被丢弃，其他卡片只在释放后变化。
- 统一启动脚本仍指向旧的非 `x64` WorkspacePanel 输出目录，导致手动验收实际启动 16:06 的旧 DLL，而自动构建和真实回归使用 17:37 的 `x64\Release` DLL。

## 修复

- 四种卡片模板统一由卡片根表面接收指针事件，编辑模式下可从非交互内容区或拖动柄开始拖动；
- 按钮和文本框仍保留自身输入，不被根表面抢占；仅接受鼠标左键拖动；
- 投影器优先把被拖卡片锚定到边界夹紧后的目标单元，再按当前视觉顺序确定性重排冲突卡片；
- 其他卡片优先保留当前逻辑单元，冲突时使用稳定 first-fit 填充可用位置，保证无重叠、无越界；
- 指针移动时原地更新非拖动卡片的 `CardSurfaceItem.Placement` 并使网格重新布局，不替换 ItemsRepeater 数据源；
- 被拖卡片保持原布局基准，只使用现有 `CompositeTransform` 1:1 跟随指针，避免预览重建导致 pointer capture 丢失；
- 取消、捕获丢失或非法落点会恢复已提交 placement；释放成功后一次性提交完整投影。
- `Run-WinWidgetBoard.ps1` 改为启动本次构建和真实回归使用的 `artifacts\bin\WinWidgetBoard.WorkspacePanel\x64\Release\...` 产物。
