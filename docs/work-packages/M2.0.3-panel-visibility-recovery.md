# M2.0.3 面板可见性业务方法与重连恢复

状态：已完成；Debug/Release 测试、真实 CoreBroker + WorkspacePanel 进程 smoke 和原生 LauncherHost 重试 smoke 均已通过
关联需求：PNL-004、G-006、NFR-REL-001
关联 ADR：ADR-0002、ADR-0008、ADR-0009

## 目标

在已有 Named Pipe 会话上增加第一个真实业务方法 `panel.report-visibility`，验证状态设置式命令的幂等重复提交，以及 WorkspacePanel 在 CoreBroker 重启后重新握手并恢复最新可见性状态。

## 允许修改

- `src/Contracts/Protocol/PanelVisibility.cs`；
- `src/CoreBroker/Commands/` 与 CoreBroker IPC 路由；
- `src/CoreBroker.Client/` 和 `src/WorkspacePanel/Ipc/`；
- WorkspacePanel 的测试 smoke 入口；
- `tests/UnitTests/`、API 契约、ADR、实施状态和本工作包。

## 禁止修改

- 不引入 SQLite、迁移、布局、卡片实例或插件业务；
- 不让 LauncherHost 读取面板/卡片数据或承担业务方法；
- 不把进程内 revision 或 operation 缓存描述为跨重启持久化；
- 不记录 session token、完整 payload 或敏感显示器标识。

## 实现

- `panel.report-visibility` 请求包含 `clientOperationId`、`panelVisible` 和可选 `displayId`；
- CoreBroker 对同 ID 同 payload 返回相同业务结果，对冲突 payload 返回 `validation.invalid-argument`；
- 去重表有界，避免无界内存增长；
- WorkspacePanel 初次会话建立后上报可见性；心跳发现重连后重新上报最新目标状态；
- `--broker-smoke-test` 构造真实 WinUI 面板、连接生产 CoreBroker 并上报可见性后退出。

## 真实进程验收

启动 CoreBroker Release，并向子进程注入同一 `WINWIDGETBOARD_COREBROKER_SESSION_TOKEN` 后运行：

```powershell
& .\artifacts\bin\WinWidgetBoard.WorkspacePanel\x64\Release\net10.0-windows10.0.26100.0\win-x64\WinWidgetBoard.WorkspacePanel.exe --broker-smoke-test
```

退出码 `0` 才表示真实 WinUI 进程完成握手、业务上报和清理。令牌缺失、Broker 不可用或业务响应错误时返回 `21`，不得把普通面板 smoke 的退出码 `0` 当作业务方法证据。

本轮证据：Release CoreBroker 已就绪，WorkspacePanel `--broker-smoke-test` 返回 `0`；更新后的 LauncherHost Release `--corebroker-smoke-test` 返回 `0`，无令牌回归仍返回 `19`。LauncherHost 连接阶段对启动时序错误做 1 秒内有界重试。

## 完成边界

本工作包完成后可以表述为“面板可见性业务方法、有限期内幂等去重和 Broker 重启后的安全状态重报已实现并通过验证”。它不代表布局/卡片命令、跨重启持久化 revision、数据库恢复或完整产品业务已完成。
