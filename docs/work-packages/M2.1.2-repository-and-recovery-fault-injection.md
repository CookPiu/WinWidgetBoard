# M2.1.2 数据仓储基础与恢复故障注入

状态：已完成；Debug/Release 48/48 单元测试通过
关联需求：DAT-001、NFR-REL-002、NFR-REL-003、NFR-SEC-002
关联 ADR：ADR-0002、ADR-0005

## 目标

在 M2.1.1 的 `winsqlite3.dll` 基础上提供可测试的参数化数据访问边界、事务接线和确定性故障注入，验证数据库写入失败时不会留下半提交状态。

## 本次交付

- `SqliteStatement`：参数绑定、逐行读取、空值读取和 statement 生命周期管理；
- `SqliteTransaction`：显式提交、回滚和未提交自动回滚；
- `SqliteRepository`：通用参数化执行、查询和事务入口，不向 UI 暴露可变数据库实体；
- `IPersistenceFaultInjector`/`PersistenceFaultInjector`：覆盖打开、迁移、备份、恢复、写入和提交节点，默认是 no-op，可配置一次性故障；
- `SqliteRecoveryManager`：将备份复制到新的隔离恢复文件，不覆盖活动数据库；
- 数据库打开、迁移和迁移事务接入故障注入；
- `SqliteStatementTests` 与 `PersistenceFaultInjectionTests`，覆盖正常参数化访问、提交/回滚、打开失败、迁移回滚、写入失败、提交失败、备份失败和恢复失败。

## 明确不做

- 不实现卡片、布局、便签、待办、日历或计时器领域 CRUD；
- 不接入 CoreBroker IPC、LauncherHost 或 WorkspacePanel；
- 不创建剪贴板历史表，也不持久化剪贴板正文；
- 不自动用恢复副本替换活动数据库；后续恢复策略需单独工作包和验收。

## 验证
