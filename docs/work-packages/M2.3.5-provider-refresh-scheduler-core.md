状态：已完成

关联需求：CRD-001、CRD-002、CRD-003、CRD-005、WEA-001、
NFR-PERF-003、NFR-PERF-007

关联规范：`docs/03-technical-architecture.md` 第 10～11 节、

`docs/08-testing-strategy.md` 第 6.5、8.3 节

关联 ADR：ADR-0002、ADR-0004、ADR-0005、ADR-0017。本包沿用
CoreBroker 负责统一 Provider 调度的既有进程边界，不新增 IPC、持久化、网络、
插件或验收数据路径，因此不新增 ADR。

## 目标

在 CoreBroker 内建立 Scheduled Provider 的纯 C# 集中调度核心。调度器按稳定
Provider 请求键合并相同来源工作，使用注入的时钟和随机源确定 cadence、timeout、
指数退避、抖动与手动刷新限流，并把不可变 Provider 结果交给纯 sink。

本包证明调度合同和内存 fake 行为，不代表天气、HTTP、CoreBroker Provider IPC、
跨重启缓存或真实系统节能事件已经完成。

## 冻结范围

### Provider 合同

- `ProviderRequestKey` 由 provider ID、capability、数据源键和规范化参数指纹组成；
  instance ID 不进入合并键，不同城市或参数不得误合并；
- `ScheduledProviderDescriptor` 声明 minimum、visible、hidden、power-saver cadence，
  request timeout、网络需求、手动刷新能力/最小间隔和退避参数；
- hidden/power-saver interval 为 `null` 表示暂停；所有非空 cadence 不得短于
  Provider minimum interval；
- `ProviderRefreshRequest`、`ProviderRefreshResult` 深拷贝 JSON，携带 request ID、
  generation、deadline/produced/valid-until、错误码和可选 Retry-After；
- 结果类型覆盖 Success、Empty、Offline、PermissionRequired、Unavailable、Failed、
  RateLimited、TimedOut；用户、可见性和 Dispose 取消不生成错误结果；
- `IProviderRefreshSource` 与 `IProviderRefreshSink` 不引用 WorkspacePanel、WinUI、
  HTTP、IPC 或数据库。

### 退避策略

- 第 `n` 次连续失败的原始延迟为
  `min(BaseDelay × 2^(n-1), MaxDelay)`，实现必须溢出安全；
- jitter 使用注入的 `[0,1)` 样本做对称抖动并保持在配置上限内；
- Retry-After 是重试下限，最终仍受配置上限约束；
- 成功重置失败计数由 scheduler 状态机负责；取消、隐藏和暂停不增加失败计数。

### 集中调度

- Scheduler 只支持 Scheduled Provider；Event、PersistentTask、Sync 和 Plugin
  Provider 留待独立工作包；
- 相同 request key 同时最多一份有效请求；多个订阅 fan-out，单个 sink 异常不影响
  其他订阅；
- 使用显式 `PumpDueAsync` 由未来唯一宿主循环驱动。本包不创建每卡 Timer、永久循环
  或 UI DispatcherTimer；
- cadence、timeout 和 backoff 使用可注入 `IProviderRefreshClock` 的单调时间，
  生产适配器由 `TimeProvider` 提供；UTC 只用于
  request/result metadata，不因墙钟跳变产生刷新风暴；
- network/power/visibility 输入是幂等状态设置。恢复只触发一次重新评估；
- manual refresh 最多绕过一次当前 backoff，仍受最小间隔、Retry-After、同 key
  in-flight 去重和可见性门禁；
- unregister/hide/pause/Dispose 递增 generation 并取消消费者。Provider 忽略取消时，
  迟到结果不得提交；每 request key 的在途/前驱工作和 pending 标志必须有界；
- 全局 registry lock 内不得调用 source、sink 或其他外部回调；Dispose 使用单一共享
  有界预算并观察迟到 fault。

## 与现有卡片 Runtime 的边界

- `CardRuntimeVisibilityScheduler` 继续只负责 WorkspacePanel 的 panel/viewport 生命周期、
  Visible 首次本地快照和 generation/identity/commit gate；本包不修改它；
- Provider scheduler 位于 CoreBroker，不引用 `CardRuntimeInstance` 或
  `CardRuntimeSnapshot`；
- `validUntilUtc` 保留在内部 Provider result metadata。本包不扩展现有
  `CardRuntimeFreshness`/wire snapshot 的 `expired` 值；Provider result 到卡片快照、
  `cards.subscribe` IPC 和 UI dispatcher adapter 由后续工作包完成；
- 失败结果不清除 scheduler 内最后成功结果，但 Stale/Offline/Error、payload 和
  allowed actions 的最终卡片映射不在本包声称完成。

## 自动验证计划

合同与退避：

- UT-CARD-071：descriptor/interval/timeout/ID guard；
- UT-CARD-072：request/result JSON ownership 与 metadata；
- UT-CARD-073：request key 相等和参数隔离；
- UT-CARD-074：指数退避、上限和溢出；
- UT-CARD-075：确定性 jitter 与边界；
- UT-CARD-076：Retry-After 下限、上限及非法输入。

集中 scheduler：

- UT-CARD-077：同 key 合并一次 fetch 并 fan-out；
- UT-CARD-078：不同 source/参数不合并；
- UT-CARD-079：visible/hidden cadence 与重复 pump 去重；
- UT-CARD-080：网络/节能暂停和恢复只重新评估一次；
- UT-CARD-081：timeout 分类、取消语义和 last-success 保留；
- UT-CARD-082：失败退避、成功复位与确定性 jitter；
- UT-CARD-083：手动刷新一次 bypass、限流和 in-flight coalesce；
- UT-CARD-084：单 sink/source 异常隔离；
- UT-CARD-085：隐藏/注销/同 ID 复用拒绝迟到结果；
- UT-CARD-086：墙钟前后跳不改变单调 due/timeout；
- UT-CARD-087：快速状态信号保持 pending/in-flight 有界；
- UT-CARD-088：Dispose 有界、幂等并观察迟到 fault；
- UT-CARD-089：忽略取消的 Provider 前驱保持每 key 有界；
- UT-CARD-090：执行中新增 consumer 只触发一次有界 follow-up；
- UT-CARD-091：任意失败类型的 Retry-After 均阻止手动绕过；
- UT-CARD-092：同组复用 subscription ID 不接收旧 fan-out；
- UT-CARD-093：clock、jitter 和 descriptor 外部 seam 不在 registry lock 内；
- UT-CARD-094：抛异常的取消回调不污染 timeout、隐藏、其他 group 或 Dispose；
- UT-CARD-095：network/power/visibility 暂停恢复不缩短既有 backoff；
- UT-CARD-096：最后订阅注销后的 tombstone 仍约束同 key 忽略取消工作；
- UT-CARD-097：旧 registration handle 不会注销复用 ID 的新 consumer；
- UT-CARD-098：process-fatal 异常分类不会被归一为普通 Provider 失败。

所有测试使用 fake source/sink、可控 `IProviderRefreshClock` 和确定性 jitter，不使用 sleep、
真实 HTTP、WinUI、IPC、SQLite 或生产数据。
