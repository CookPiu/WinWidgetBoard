# M2.3.6 Provider 生产宿主与卡片快照边界

状态：已完成

关联需求：CRD-001、CRD-002、CRD-003、CRD-005、NFR-PERF-007

关联规范：`docs/03-technical-architecture.md` 第 10～12 节、
`docs/07-api-contracts.md` 第 7、10、15 节、`docs/08-testing-strategy.md` 第 6.5 节

关联 ADR：ADR-0002、ADR-0005、ADR-0017、ADR-0018。

## 目标

把 M2.3.5 的纯调度核心接入 CoreBroker 的唯一生产 pump 生命周期，并建立 Provider
结果到共享 `CardStateSnapshot` 的纯适配边界，为后续 `cards.subscribe` 长连接传输保留
有界事件缓冲。进程级不可恢复异常必须能被宿主观察，而不能伪装成普通 Provider 失败。

## 冻结范围

- `ProviderRefreshHost` 是唯一生产 pump owner；按注册组计算下一次 due，空闲时使用
  有界轮询间隔，不创建每 Provider Timer；
- `ProviderProcessFatalSupervisor` 只接收进程级不可恢复异常，重复 fault 只触发一次
  终止策略；
- `CardsContract` 定义 `cards.subscribe` 请求、初始响应、`cards.snapshot` 事件和
  `CardStateSnapshot` DTO；
- `ProviderCardSnapshotAdapter` 维护每实例 sequence，映射成功、空、离线、权限、不可用、
  超时、限流和失败状态，复制 JSON payload，并保留显式动作门禁；
- `CardSnapshotEventBuffer` 按 instance ID 合并状态事件，超出容量标记 overflow；
- CoreBroker 生产入口创建 host、scheduler 和 fatal supervisor，但当前没有注册真实
  Provider，仍由后续工作包接入。

## 明确不包含

- `cards.subscribe` Named Pipe 长连接事件发送、断线重连和跨进程 backpressure；
- WorkspacePanel 的 UI dispatcher 订阅和真实卡片状态替换；
- 天气数据源、HttpClient、DNS/TLS、网络权限、域名 allowlist；
- SQLite Provider cache、last-success 持久化、迁移和隐私页；
- OS 网络/电源/睡眠事件、EcoQoS、WPR/WPA 和长稳性能结论；
- 第三方 Provider、PluginHost 和插件沙箱。

## 自动验证

- `CT-CARD-001/002`：订阅与快照合同、JSON 枚举和标识符边界；
- `UT-CARD-099/100`：Provider 结果状态、freshness、sequence、诊断码、动作和 payload 所有权；
- `UT-CARD-101`：事件按实例合并且慢消费者达到上限时标记 overflow；
- `UT-CARD-102/103`：唯一 pump、注册生命周期和 scheduler consumer 注销；
- `UT-CARD-104`：进程级 Provider fault 到 supervisor 的单次观察路径。

所有测试使用 fake source/sink、注入时钟和测试终止回调，不使用真实 HTTP、WinUI、SQLite、
睡眠等待或生产数据库。

## 验收证据

- 新增测试 8 项全部通过；全量 UnitTests Debug/Release 均为 273/273；
- CoreBroker 与 WorkspacePanel Debug/Release x64 构建均为 0 警告、0 错误；
- 生产入口已创建 host，但由于没有真实 Provider 注册，尚未证明真实数据刷新、IPC 事件
  传输或 OS 节能事件接入；证据等级为 E1/E2（合同和宿主生命周期）。

## 完成门禁

- Provider host 只能启动一个 pump loop；
- 注册注销不会遗留 scheduler consumer；
- fatal fault 不进入普通 Provider 失败结果；
- snapshot sequence、payload 和事件缓冲均有界；
- 文档明确 `cards.subscribe` transport 和真实 Provider 仍未完成；
- `git diff --check`、相关测试和 Debug/Release 构建通过。
