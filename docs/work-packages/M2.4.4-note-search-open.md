# M2.4.4 NTE-001 从搜索结果打开便签

状态：已完成代码与自动测试；真实桌面搜索结果打开回归待完成
关联需求：NTE-001、NFR-REL-002、NFR-A11Y-002
关联规范：便签搜索结果打开与草稿保护规范
关联 ADR：ADR-0010、ADR-0013

## 目标

让用户可以从便签搜索结果打开对应的已保存便签，并将其载入现有编辑器；如果当前便签存在未保存草稿，必须阻止切换，避免覆盖用户输入。

## 实现范围

- `NoteEditorViewModel` 支持在无未保存改动时加载另一个已保存便签；
- 搜索结果变为可访问按钮，点击后载入目标便签；
- 正在保存或存在未保存草稿时禁用结果列表；
- 目标便签不存在或加载失败时保留当前便签并显示明确状态；
- 增加中英文成功、失败和草稿保护文案；
- 不改变 revision token、自动保存或删除策略。

## 不在本工作包内

- 新增、删除、归档和恢复历史；
- 多窗口或多编辑器并行编辑；
- Markdown 渲染和编辑工具栏；
- 冲突合并 UI；
- Windows 剪贴板历史卡片。

## 自动验证

- `UT-NOTE-017`：无未保存改动时可打开搜索选中的已保存便签；
- `UT-NOTE-018`：存在未保存草稿时拒绝切换并保留草稿；
- `UT-NOTE-019`：目标便签不存在时保留当前便签；
- Debug/Release UnitTests：目标为 121/121；
- WorkspacePanel Debug/Release x64 构建和 WinUI smoke：目标为 0 警告、0 错误、退出码 0。

## 真实桌面验证

在可交互 Windows 桌面中使用当前 `x64\Release` 面板搜索已保存便签，点击结果按钮并确认标题、正文和保存状态切换到目标便签；编辑当前便签产生未保存草稿后再次点击搜索结果，确认切换被阻止且草稿仍在。该验证需要真实 UIA、前台输入和 CoreBroker 数据，不由单元测试替代。
