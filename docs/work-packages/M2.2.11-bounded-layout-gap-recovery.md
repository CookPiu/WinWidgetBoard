# M2.2.11 LYT-004/005/DAT-001 持久化空行与拖动视觉恢复

状态：已完成代码、自动测试和当前真实持久化布局回归；完整显示矩阵待完成
关联需求：LYT-004、LYT-005、DAT-001
关联 ADR：ADR-0003、ADR-0014、ADR-0015

## 缺陷

- 当前用户数据库 revision 18 中，紧凑布局只需 3 行，但 `demo.timer` 的 `preferred_row` 为 7，导致大段整行空白和卡片落入远离初始视口的位置；
- WorkspacePanel 在异步布局加载前已按默认顺序实现 ItemsRepeater 模板，持久化顺序重放后出现模板标题、卡片身份和 placement 不一致；
- 实时预览会显式使网格失效，但释放提交后只更新 `CardSurfaceItem.Placement`，未触发自定义 `CardGridLayout` 重新 Arrange，造成让位卡片移动而被拖卡片停在旧坐标并视觉重叠；
- 原真实回归未等待持久化布局加载完成，不能稳定覆盖用户实际启动链。

## 修复

- 新增 `CardLayoutReplaySanitizer`：忽略 preferred row 计算紧凑基线，只保留不超过紧凑底部 2 个空行的保存位置，异常项在内存中回退到确定性 first-fit；
- 启动恢复不会自动写库；状态栏提示用户点击“完成”后才保存恢复位置；
- `CardLayoutSurfaceViewModel` 以稳定对象身份同步卡片，并只在成员或身份顺序变化时发布结构变化；
- 有 Broker 时先加载/恢复布局再首次绑定 ItemsRepeater；无 Broker 或无保存布局时明确选择默认布局后再绑定，避免先实现错误模板；
- 所有已提交 `Placements` 变化都调用 `CardGridLayout.InvalidatePlacements()`，确保自定义布局重新 Measure/Arrange；
- 真实桌面脚本在拖动前等待布局恢复或离线初始化状态，`-WithBroker` 覆盖生产 Broker 和当前数据库。

## 人工验收

1. 关闭旧 WinWidgetBoard 进程；
2. 从统一入口启动 Release x64；
3. 确认状态栏显示异常空行已恢复；
4. 点击“编辑”，从计时器或日历的非交互表面拖到另一卡片位置，确认被拖卡片 1:1 跟随、另一卡片让位、释放后无重叠；
5. 点击“完成”保存恢复位置；
6. 关闭并重开，确认不再出现第 7 行大空白。
