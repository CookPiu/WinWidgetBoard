# ADR-0001：稳定版任务栏入口使用独立覆盖窗口

状态：Accepted
日期：2026-08-06

## 背景

产品希望在 Windows 11 左下角、原 Widgets 入口附近放置自己的按钮。Windows 没有公开、稳定的任意任务栏内容插槽 API。现有项目通常选择：

1. Explorer/XAML 注入；
2. 独立覆盖窗口；
3. AppBar 独立停靠条；
4. 普通托盘图标；
5. 屏幕边缘浮动按钮。

TaskbarWidgets 能实现真正任务栏内组件，但明确依赖未公开 XAML Diagnostics 和视觉树。

## 决策

稳定通道使用应用独立拥有的 Win32 覆盖窗口：

- 不进入 Explorer；
- 从显示器和工作区矩形推导任务栏边缘；
- 用户确认安全位置；
- 只在按钮区域接收输入；
- 冲突或几何不明确时使用 EdgeTabFallback；
- 用户手动关闭原生 Widgets。

不劫持 `Win+W`。

## 理由

- Windows 更新影响限定在位置算法；
- 崩溃不会拖垮 Explorer；
- 可独立恢复；
- 可测试鼠标穿透；
- 可在失败时隐藏；
- 符合低权限原则。

## 放弃方案

### Explorer 注入

放弃原因：

- 私有 API；
- 累积更新可能破坏；
- 崩溃影响 Shell；
- 安全和维护成本过高。

### AppBar

AppBar 创建独立占用工作区的条带，不是原任务栏内按钮。可作为未来“固定工作栏”模式，但不是默认入口。

### 仅托盘图标

稳定但不满足左下角体验，可作为恢复/诊断后备入口。

## 后果

正面：

- 核心稳定；
- 不污染 Explorer；
- 安装和卸载简单。

负面：

- 无法让系统任务栏图标自动为入口腾位；
- 左对齐和第三方 Shell 可能冲突；
- 自动隐藏需要专门适配；
- 可能需要安全位置编辑器。

## 验证

M1 必须真实验证：

- 任务栏居中/左对齐；
- 自动隐藏；
- 1～3 显示器；
- 100%～200% DPI；
- Explorer 重启；
- 全屏；
- 系统按钮不被覆盖；
- 非按钮区域点击穿透。

若失败，选择 EdgeTabFallback，而不是回退到注入。
