# ADR-0004：MVP 不开放第三方插件，后续插件需要真实沙箱

状态：Accepted
日期：2026-08-06

## 背景

产品需要长期扩展卡片。仅把插件放到独立进程可避免核心崩溃，但插件仍可能以当前用户权限访问文件、网络、剪贴板和进程。

若权限界面声称可以阻止这些访问，而实际只使用 Job Object，则构成虚假安全边界。

## 决策

MVP：

- 只提供内置可信卡片；
- 建立内部 Card/Provider 接口；
- 不提供第三方安装入口。

后续：

- 插件分 builtin、brokered、fullTrust；
- brokered 必须采用 AppContainer、WASM capability host 或等价真实沙箱；
- 默认 UI 为声明式 Schema；
- fullTrust 明确警告并允许策略禁用；
- 所有插件运行与核心进程隔离。

## 理由

- 先验证产品核心；
- 避免过早锁定 SDK；
- 避免权限承诺不真实；
- 降低供应链风险；
- 保持 WorkspacePanel 无不可信 DLL。

## 后果

正面：

- 首版安全边界清晰；
- 核心进度不被插件平台拖慢；
- 可根据真实卡片需求设计 SDK。

负面：

- 首版扩展性仅限源码内扩展；
- 插件阶段成本较高；
- 可能需要 WASM/AppContainer 专项技术验证。

## 门禁

第三方安装前必须完成：

- 沙箱 ADR；
- 包格式；
- 权限执行；
- 更新和回滚；
- fuzz；
- 安全审查；
- 漏洞渠道；
- SDK 兼容策略。
