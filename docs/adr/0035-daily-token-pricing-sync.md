# ADR-0035：Token 定价每日从 LiteLLM 开源价表同步

状态：Accepted
日期：2026-09-02
关系：修订 [ADR-0030](0030-token-usage-card.md) 第 9 条「费用估算」与其「零网络」后果；
ADR-0030 的用量读取、去重、不落库等其余结论不变。
[ADR-0020](0020-open-meteo-weather-provider.md) 中「Open-Meteo 是唯一外部网络供应商」的表述自本
ADR 起不再成立，新增第三个端点。

## 背景

ADR-0030 把费用估算建立在一张手工维护、带核验日期的价表上，并在后果里写明：
**「手工维护的价格表会静默过期，过期的价格本身不会自我暴露。」** 这条在 2026-09-02 兑现了：
用户当天把 Claude Code 切到新发布的 `claude-fable-5-1`，价表里没有这个 id，精确匹配拒绝猜测，
于是当日全部用量无价，`TodayCostUsd` 为 0，卡片把「今日花费」整块隐藏——一张用量卡片一夜之间
丢掉了它存在的那个数字，且界面上没有任何说明。

发布版不能靠每次厂商发新模型就出一个版本来跟上价格；价格必须在不发版的情况下更新。

## 决策

1. **来源：LiteLLM 的 `model_prices_and_context_window.json`**（GitHub `BerriAI/litellm` 主分支的
   raw 文件，MIT）。它是当前唯一持续跟随厂商公开价的机读价表；Anthropic 与 OpenAI 都没有官方的
   机读定价接口。2026-09-02 核对：文件 2.0 MB、3518 条，`claude-fable-5-1`、`claude-opus-5`、
   `claude-sonnet-5` 与 `gpt-5.6-sol/terra/luna` 的数值与厂商定价页逐项一致。
2. **每日一次，条件 GET**。Broker 内一条后台循环：启动时先应用数据库里上次的结果，然后按
   「从未取过 → 立刻；成功后 24 小时；失败后 1 小时」的节奏取一次，带 `If-None-Match`，
   未变化只花一个 304。请求不带账号、设备或安装标识，只有 User-Agent。
3. **只保留能用的几十行**。用 `Utf8JsonReader` 流式过一遍，只留 `litellm_provider` 为
   `anthropic`/`openai`、id 形如 `claude-*` / `gpt-*` 的一方条目；带供应商前缀的路由别名
   （`bedrock/...`、`openrouter/...`）一律丢弃——它们计费不同，这与 ADR-0030「不做家族匹配」是同一条
   原则。缺失的缓存字段按厂商公开的倍率补：5 分钟写入 1.25× 输入，1 小时写入缺省等于 5 分钟档
   （OpenAI 没有 1 小时档），缓存读取 0.1× 输入。
4. **同步价优先，内置表兜底**。`TokenUsageRateBook` 先查同步价、再查内置表：同步价比任何构建都新，
   内置表则保证离线机器或关掉同步的机器价出与以前完全相同的数。内置表继续带 `VerifiedOn`，
   本 ADR 顺带补入 `claude-fable-5-1` / `claude-mythos-5-1`（缓存读取 0.025× 而非 0.1×）。
5. **落盘的只有价格**：一行 `token_usage_pricing`（过滤后的价表 JSON、ETag、取回时间，迁移 9）。
   用量数字依旧不写库。
6. **用户可关，也可即刻拉**：`tokenusage.settings` 增加 `syncPricing`（默认开），关闭后 Broker 不再
   自发取回、只用内置表；打开时立即触发一次取回而不是等到明天。开关旁另有「立即同步」按钮
   （`tokenusage.pricing.sync`，异步、不持路由锁），是用户的一次显式动作，不受开关约束。
   设置页显示价表最近更新时间与来源。
7. **无价时说明而不是沉默**：全部用量都无价时，卡片在花费位置显示「N 个模型无价格，未计入」。
   ADR-0030 只在有金额时加 `+` 后缀，金额为零时什么都不说，正是本次被发现的形式。

## 理由

- 价格是这张卡片唯一「看不出错」的数：token 数错了会显得离谱，价格过期只是偏低。唯一的治法是
  让价格独立于发版周期更新；
- LiteLLM 价表被 LiteLLM 自身的计费与大量成本工具依赖，出错会被大量用户同时发现；把它当
  「公开事实的机读副本」而不是权威——本产品仍标注为按公开价折算的估算；
- 过滤到一方 id 后，落盘与内存里都不存在其他供应商的数据，Broker 的复杂度与隐私面没有随文件
  大小增长。

## 后果

正面：

- 新模型发布当天即可定价，`claude-fable-5-1` 一类的空白不再出现；
- 用户关掉同步即回到 ADR-0030 的零网络状态，行为完全等价。

负面：

- 产品从两个网络端点变成三个（`raw.githubusercontent.com`），docs/03、docs/09 随本 ADR 更新；
- 多一个第三方数据源：其数值错误会直接进入估算。缓解：只在该数为估算的语义下使用（`≈`），
  内置表仍由本项目按厂商页核对，并作为对照写在状态页；
- GitHub raw 不可达的地区只能用内置表，效果等同关闭同步；
- 响应上限 8 MiB，文件按当前增速数年内不会触顶，触顶时拒绝并保留旧价。

## 门禁

- 换来源必须再出 ADR：来源决定了估算的可信边界；
- 不得为了覆盖更多模型放宽 id 过滤到前缀匹配，理由见 ADR-0030 第 9 条；
- 不得在请求里加入任何标识，不得把用量数字送出本机——同步是单向拉取。
