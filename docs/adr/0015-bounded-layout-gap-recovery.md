# ADR-0015：有界恢复异常持久化布局空行

状态：Accepted
日期：2026-08-08

## 背景

ADR-0014 允许持久化逻辑网格行列，以恢复用户主动留下的空位。但逻辑行没有上界时，异常或历史拖动结果可能把卡片保存到远离其他卡片的位置。

实际复现数据库的布局修订为 18：紧凑排布只需 3 行，`demo.timer` 却保存于第 7 行。面板重开后产生大段整行空白，卡片落到初始可交互区域之外；从当前视口拖动时，单次放置偏移也不足以跨越该距离，表现为“完全不可拖动或无法吸附”。

## 决策

仅在持久化布局加载阶段执行有界恢复：

- 先忽略 preferred row，按现有顺序、跨度和 preferred column 计算紧凑布局的底部行；
- 允许 preferred row 最多超过紧凑布局底部 2 行，以保留用户有意留下的小空位；
- 超过该边界的项目仅在内存中清除 preferred row，并由既有确定性 first-fit 重新放置；
- 不自动写入数据库；用户进入编辑模式并点击“完成”后，才保存当前恢复位置；
- 不修改 preferred column、尺寸跨度、响应式列数规则或绝对像素坐标；
- 一般网格打包仍遵守 ADR-0014，边界只适用于持久化布局重放。

## 理由

- 消除把卡片隔离到屏外、导致无法直接操作的异常空行；
- 保留普通的用户布局留白，不把所有布局强制压紧；
- 恢复行为可见、可撤回，且不会在程序启动时静默改写用户数据库；
- 复用现有 first-fit 与完成编辑保存路径，不引入第二套布局算法。

## 后果

正面：

- 历史异常布局可在下一次启动时恢复到可交互区域；
- 用户确认前，持久化布局保持不变；
- 拖动仍保持 1:1 跟随、抓取偏移和释放提交。

限制：

- 超过紧凑底部 2 行的有意大空位也会在重放时被视为异常；
- 用户必须点击“完成”才能把恢复后的位置写回数据库。

## 验证

- `UT-GRID-030` 验证实际第 7 行模式回退到紧凑可交互位置；
- `UT-GRID-031` 验证边界内的小空位仍可重放；
- 连接真实 CoreBroker 和当前持久化数据库运行卡片表面与拖动手柄双路径回归；
- 回归后检查数据库在未点击“完成”时没有被自动改写。
