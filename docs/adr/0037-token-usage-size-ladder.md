# ADR-0037：Token 用量卡片按行数与列数分档，四列档并排排布

状态：Accepted
日期：2026-09-10
关系：修订 [ADR-0036](0036-token-usage-spend-curve-card.md) 第 3 条与第 4 条中「只在两行高的卡片显示」
与「一条而不是一行一条」的适用范围；ADR-0036 的曲线口径、指针跟随、载荷字段等其余结论不变。

## 背景

ADR-0036 定下卡片的内容，但阶梯只有「一行 / 两行」一个判据，宽度不参与。实测五档：

- `W`（四格宽、一行高）与 `XL`（四格宽、两行高）分别是 `M` 与 `L` 被拉宽的结果，右侧约 356 DIP 整片空着；
- 一行卡片的内容纵向堆叠，读数拿花费与页签之后剩下的高度：`M` 与 `W` 各剩 14 DIP，一条读数都放不下，
  而一格宽的 `S` 因为不显示页签反而放得下一条——**放大卡片会丢内容**；
- 读数行的 `1.5*/1*/1*` 在两头都退化：`S` 上约 130 DIP 分成 55/37/37，次要数值放不下；
  四列档上分成 300/136/136，名称与数值之间隔着 250 DIP 空白。

## 决策

1. **页签移入卡片头部行**，与设置齿轮并列，不再占内容流。它选择整张卡片显示哪一页，属于卡片 chrome；
   在内容里要 30 DIP，正是两格卡片仅有的那条读数。标题取星号列并可省略：厂商多到放不下时先截卡片名，
   不截说明当前在看谁的页签。编辑模式下页签与齿轮一起让位。
2. **四列档（`W`/`XL`）三栏并排**：花费 | 双砖 | 读数，每栏各拿卡片整高。并排与堆叠是**同一套模板的
   两组单元格**，`Grid.Row` / `Grid.Column` / `Grid.ColumnSpan` 由 `CardSurfaceItem` 算出并绑定，
   树里只有一份读数列表、一个自动化 ID——与天气卡片的宽档同一机制。
3. **双 KPI 的门槛由「两行」改为「有自己的一块地方」**：`L`/`XL` 是第二行，`W` 是第二栏。
4. **拆分在 `XL` 上展开为逐切片行**（最多五条，各带金额、占比与占比条），`L` 及以下仍是单条计量条。
   两种形态互斥。
5. **一格卡片的读数行只有两栏**：数值横跨两个数字栏，次要数值不画。它仍留在自动化名称里。
6. **行间距用各块自己的下外边距，不用 `RowSpacing`**；栏间距用 `Grid.ColumnSpacing`。

## 理由

- 判据必须同时看行数与列数：`W` 和 `M` 一样矮，它多出来的是宽度，而堆叠用不上宽度——这与天气卡片
  把逐小时走势放进 `W` 空着的右半是同一条结论；
- 并排之后各块不再互相扣预算，双砖在一行高的卡片上因此变得可能：它花的是第二栏，不是花费的高度；
- ADR-0036 选单条计量条的理由是「一条计量条比一张表便宜 80 DIP，正好装进两行卡片剩下的空间」。
  `XL` 的并排带之下恰好有那块空间，这是当时不存在的一档，所以是补充而非推翻；
- `RowSpacing` 对空行同样计费。四档里只有 `W` 只用第一行，18 DIP 的空行间距会把它仅剩 2 DIP 余量的
  读数最后一行推进裁剪线；下外边距只在块与块之间产生，空块不产生。

## 后果

- 卡片头部行在两格宽、三个页签时余量约 14 DIP；再多一个厂商会开始省略卡片标题；
- 四列档的曲线跨全部三栏，因而高度等于并排带的高度（约 91 DIP）而不是花费块的高度：
  它在这两档上是整条带的衬底；
- 同一张卡片在 `L` 与 `XL` 上对拆分的呈现不同，改尺寸会换一种形态——与天气卡片预报的堆叠/并排一致。

## 门禁

改动卡片的尺寸阶梯或并排单元格，需按 `docs/02-ux-design-spec.md` §3.7 的高度账重新核一遍，
并在真实桌面逐档确认：五档均无内容被卡片自身裁切，`W`/`XL` 的三栏不越界，指针在整条带上都能唤出十字线。
