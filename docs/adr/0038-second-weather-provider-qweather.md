# ADR-0038：天气新增和风天气数据源，凭据以 DPAPI 加密落库

状态：Accepted
日期：2026-09-10
关系：修改 [ADR-0020](0020-open-meteo-weather-provider.md) 的「Open-Meteo 是唯一天气 Provider」结论；
扩展 [ADR-0027](0027-weather-location-search.md) 的地点搜索为按数据源分流；
不改变 [ADR-0021](0021-weather-location-settings.md) 的版本化保存与运行时替换流程

## 背景

Open-Meteo 是唯一的天气来源（ADR-0020）。它无需账号、无设备标识，隐私边界最小，
这些优点没有变。问题只有一个：**中国大陆网络到 `api.open-meteo.com` 与
`geocoding-api.open-meteo.com` 的连通性不可依赖**。天气卡片因此在一整类网络下退化为
Offline/Stale，而这不是可以靠重试或超时调参解决的。

面向公开发布，一个在某地区必然不工作的核心能力，等于该地区没有这项能力。

国内可稳定访问的天气 API 基本都要求免费 API Key，因此接入第二家供应商的代价不是
「多写一个 provider」，而是**产品第一次需要保存用户凭据**。

## 决策

1. 新增第二个天气数据源 **和风天气（QWeather）**，与 Open-Meteo 并列，由用户在设置中二选一。
   数据库与线协议用短标识 `open-meteo` / `qweather` 记录选择；缺省与缺字段一律解释为
   `open-meteo`，因此既有行与旧客户端的含义不变。
2. `QWeatherProvider` 一次刷新并发请求三个端点（`/weather/v1/current`、`/hourly`、`/daily`），
   并**在 provider 内部把厂商差异全部吸收**，向卡片发布与 Open-Meteo **完全同形**的 payload：
   同样的字段名、同样的 WMO 天气代码、同样的公制数值。面板、任务栏入口与快照管线因此分辨不出
   数据来自哪一家。
3. 和风的天气现象代码由 `QWeatherConditionCodes` 映射为 WMO 代码。映射有损且是刻意的：
   和风区分 WMO 不区分的降水强度；霾、扬沙、沙尘暴统一落到 WMO 45（雾），因为它们都是能见度
   受损、卡片的雾态是唯一诚实的画法；热/冷预警（900/901）与未知（999）**不映射**，
   发布为「无天气代码」，卡片显示「—」而不是猜一个相近天气。
4. 白天/黑夜由**该地点当日的日出日落**（daily 响应的 `astro`）判定——和风的响应没有 is-day 标志，
   而卡片与入口的图形依赖它。取不到日出日落时退回该地点本地时间 6–18 点，而不是本机时间。
5. 时间戳按 `localTime=true` 请求后**去掉时区偏移**再发布，与 Open-Meteo 的形状一致；
   否则面板会把远端地点的时间按本机时区重新渲染。实况读数本身没有观测时间字段，
   由预报响应的偏移换算当前本地时间；两个预报都拿不到时不发布观测时间。
6. **凭据**：用户在设置中填写自己的 API Host 与 API Key。
   - Key 用 **DPAPI（当前用户作用域，`CryptProtectData`）加密**后以 base64 文本存入
     `weather_settings.api_key_protected`。不引入 NuGet 依赖，直接 P/Invoke；
     选 base64 而非 BLOB 是因为语句包装层只绑定文本。
   - Key **只写不读**：任何响应只回 `hasApiCredential` 布尔值，从不回显。保存请求里
     `apiKey` 为 `null` 表示「保持不变」，空串表示「清除」，其他值表示「替换」——
     设置对话框拿不到已存的 Key，「不变」必须可表达。
   - Key 只出现在**请求头** `X-QW-Api-Key` 上，绝不进 URL、请求键、日志或错误文本。
     该请求头挂在单条请求消息上，不挂在共享 `HttpClient` 的默认头上，否则会随
     无凭据的 Open-Meteo 流量一并发出。
   - **Host 白名单**：只允许 `*.qweatherapi.com` 与 `*.qweather.com`。Key 是 bearer 凭据，
     它被发往哪个主机属于安全边界，不是自由配置项；粘贴错或被诱导填入的第三方主机必须不可达。
     接受完整 URL 形式但只保留其 host，带路径、端口或 userinfo 的一律拒绝。
7. 解密失败的凭据**视为不存在**，而不是存储故障：从另一台机器或另一账户拷来的数据库
   仍是一份有效设置，只是没有可用的 Key。
8. 选中和风但缺 Host 或缺 Key 时注册 `UnconfiguredWeatherProvider`，它不发网络请求，
   直接返回 `weather.credentials-missing`（`PermissionRequired`）。**不静默回退到 Open-Meteo**：
   那会把读数发往用户没有选择的地方。
9. **地点搜索按数据源分流**（扩展 ADR-0027）：选中和风且凭据可用时走和风 GeoAPI
   （`/geo/v2/city/lookup`），否则走 Open-Meteo 地理编码。理由是连不上某家天气端点的网络，
   同样连不上它的搜索端点——只换天气不换搜索，等于只给了一半能力。
   ADR-0027 的全部约束不变：仅在用户提交时发生、查询与响应有界、8 秒超时、不缓存不落盘。
10. 天气 payload 仍然**不落库**（ADR-0020、0021 未变）。落库的只有位置、单位、数据源选择、
    API Host 与加密后的 Key。

## 理由

- **同形 payload 而不是新增卡片契约**：面板从 WMO 代码解析本地化天气名称，入口从同一套
  token 取字形。引入第二套天气词汇表意味着在两个进程里各维护一份对照表，
  也就意味着它们迟早会不一致。
- **DPAPI 而不是明文，也不是自带密钥**：保护范围绑定到拥有数据目录的 Windows 账户，
  与其余存储已经假设的边界完全一致；自带密钥只会让密钥和密文躺在同一个文件里。
- **Host 白名单而不是任意主机**：这是本项目第一次持有可被冒用的凭据。允许任意主机，
  等于允许一次错误粘贴把 Key 送给第三方。
- **免费额度足够**：15 分钟可见节奏、每次三请求，约 288 次/天、8.6k 次/月，
  远低于和风免费额度。

## 后果

正面：

- 大陆网络下天气卡片可用，且用户明确知道读数来自哪一家；
- 中文地名搜索走和风 GeoAPI 时返回中文行政区划，比通用地理编码更贴近国内用法。

负面与约束：

- **产品第一次保存用户凭据**，攻击面与隐私文档相应扩大，`docs/09-security-privacy.md` 已更新；
- 一次刷新是三个请求而不是一个。实况失败即整次失败，两个预报失败只丢失趋势与三日预报，
  当前读数照常发布；
- 和风自 2026 年起废弃 `devapi.qweather.com` 等共享域名，改为每账号专属 API Host，
  因此**用户必须自己填 Host**，无法内置一个默认值；
- 和风声明自 2027-01-01 起将限制 API KEY 方式的每日请求数。本产品的节奏远低于任何合理的
  日限额，但这是一个需要留意的上游变化；
- 和风文档要求中国大陆使用 GCJ-02 坐标系，而 Windows 设备定位与 Open-Meteo 搜索返回 WGS-84。
  本产品**统一按 WGS-84 存储与发送**：两者相差约数百米，对 1 公里分辨率的天气读数没有可观察
  影响，而混用坐标系会让同一份设置在两个数据源之间含义不同。

## 放弃方案

- **只加免注册的国际源（met.no 等）**：改动最小、不需要凭据，但大陆访问速度与稳定性同样无保证，
  没有解决本 ADR 要解决的问题。
- **彩云天气**：凭据最简单（一个 token 拼在 URL 路径里），单次请求拿全量数据；
  但它没有地理编码接口，且把凭据放在 URL 上与第 6 条的约束相悖。若日后需要第三家，这是首选。
- **凭据存明文**：实现最省事，本机其他进程与任何一次数据库备份都能直接读到 Key。
- **凭据只读环境变量**：代码零凭据存储，但普通用户无法在设置里填写，对公开发布的易用性不可接受。
- **自动探测可达性并在两家之间切换**：看起来最省心，但读数会在用户没有选择的情况下改变来源，
  且失败探测本身要发请求。数据源是用户的选择，不是运行时优化项。

## 验证

- `UT-WEA-077`～`UT-WEA-093` 覆盖：同形 payload 与单位换算、凭据只走请求头且不污染共享客户端、
  gzip 解压、时间戳去偏移、日出日落判定昼夜、预报失败不影响实况、401 映射为
  `PermissionRequired`、外域 Host 与畸形 Key 在构造期即被拒、未配置源报缺凭据、
  和风代码到 WMO 的映射无空洞、GeoAPI 字符串坐标与 body 状态码解析、
  Host 归一化与白名单、Key 形状校验、DPAPI 往返与不可解密即视为无凭据、
  升级后的既有行仍是 Open-Meteo 且无 Host 无凭据；
- 真实桌面：`scripts/Test-WeatherSettingsInteraction.ps1` 全流程通过
  （设置对话框打开、数据源下拉框渲染、搜索→选中→保存→运行时重载→重启后读回）。
