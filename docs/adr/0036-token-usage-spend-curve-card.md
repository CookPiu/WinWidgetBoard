# ADR-0036：Token 用量卡片以当日累计花费曲线为背景，拆分以单条计量条回归

状态：Accepted
日期：2026-09-09
关系：修订 [ADR-0030](0030-token-usage-card.md) 第 3.1 条「卡片以当日花费为主视觉，其余为读数行……不展示速率与模型占比」
中关于趋势条与占比的部分；ADR-0030 的数据来源、去重、不落库、不展示订阅配额等其余结论不变。

## 背景

ADR-0030 把卡片定为「当日花费大字 + 读数行 + 24 小时滚动趋势条」，并以「卡片高度有限」为由不展示占比。
实际使用一段时间后有三个问题：

- 趋势条按最近 24 小时滚动，最右一格永远是当前小时，与「今日花费」的口径不一致——
  凌晨看到的是昨天的形状，下午看到的仍然拖着昨夜的空格；
- 读数行把响应数与各类 token 并列成一张表，每行权重相同，读者要自己把「计费 + 缓存读取」加起来、
  把「计费 ÷ 响应数」除出来；
- 两行高的卡片在读数行之下空着一截，而曾经画在那里的拆分表因为逐行占高被裁掉后就没有再回来。

调研了主流 token 用量工具（状态栏、菜单栏弹层、终端仪表盘、本地网页）的布局后，
本机预览了六种方案，用户选定「累计曲线衬底 + 双 KPI」并要求曲线铺满整宽、跟随指针显示对应数据。

## 决策

1. **背景改为当日累计花费曲线**。横轴是 0:00 到当前时刻并拉伸到卡片整宽（右缘恒为「现在」），
   纵轴是当日总额；两个轴都不需要数据没有的上限。曲线以单调三次样条（Fritsch–Carlson）穿过各小时点：
   累计值在两小时之间既不回落也不过冲，所以指针在曲线上读到的位置不会高于后一小时、低于前一小时。曲线画在花费大字之后，
   用天气卡 motif 笔刷与其不透明度，高对比度下随之透明；折线与十字线取文本语义色，高对比度下仍可见。
   全部无价时曲线退化为累计计费 token，与大字退化为说明文字同一口径。
2. **指针跟随**。指针进入大字区域时显示 1 DIP 竖线、曲线上的圆点与一条标签：`HH:00 ≈$累计 · 本时 计费`，
   最右端标为「现在」。竖线与圆点沿曲线连续跟随指针（圆点取自所绘样条的同一函数），标签则始终写指针所在
   小时的真实读数——Broker 只有逐小时合计，小时内插值出来的金额是编造的。只动 `Translation` 与可见性、
   不做任何动画；靠右缘时标签翻到竖线左侧。
   编辑模式下曲线不接收指针，按下大字仍然发起拖动。
3. **两块 KPI 只在两行高的卡片显示**：总 token（计费 + 缓存读取，下注缓存读取量）与
   响应数（下注平均每次计费）。响应数进入 KPI 后不再作为读数行重复出现。
4. **拆分以单条计量条回归**：两个最大切片分列计量条两端（总览按厂商、厂商页按模型），
   条长为最大切片占比，各带自己的金额，无价时退回 token 数。一条而不是一行一条，
   正是当年拆分表被裁掉的原因。
5. **载荷新增字段**：每页 `spendCurve`（每小时一点，`fraction`/`level` 已归一化，
   `cumulativeCostText`/`billedText` 已排版，`isCurrent`）、`totalTokensText`、
   `averageBilledPerRequestText`；拆分切片新增 `costText`。滚动 24 小时 `trend` 字段删除。
   Broker 聚合改为按本地小时分桶，每小时带自己那份金额，与当日总额同一算法。
6. **读数行顺序改为**：今日计费、输出、缓存读取、缓存命中率、响应数。小尺寸卡片仍取前缀。

## 理由

- 累计曲线与「今日花费」是同一个数在时间上的展开，而滚动趋势条是另一个窗口里的另一个量；
- 归一化留在 Broker，面板只按当前宽度摆点，与硬件监控 `history`、天气小时条的分工一致；
- 指针跟随不引入动画，是因为它属于高频交互，任何缓动都会让十字线落后于指针；
- 一条计量条比一张表便宜 80 DIP，正好装进两行卡片剩下的空间。

## 后果

- 状态栏工具里常见的「配额 + 重置时间」行仍不纳入（ADR-0030 §2.2 未变）；
- 曲线随时间在横向被压缩，凌晨几分钟的数据会被拉满整宽——这是「右缘恒为现在」的直接代价；
- 曲线只对指针可用；键盘与读屏用户经曲线的自动化名称得知它是什么，数字仍由大字与读数行给出。

## 门禁

改动 `TokenUsageSpendCurve` 的指针逻辑或卡片模板，需在真实桌面核对：浅色与深色主题下曲线可见、
指针跨越右缘时标签翻转、编辑模式下按住大字能拖动卡片。
