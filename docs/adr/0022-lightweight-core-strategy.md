# ADR-0022：收缩为轻量核心版并采用风险分级门禁

状态：Accepted
日期：2026-08-15

## 背景

原 0.1 产品基线同时规划七类卡片、多显示器完整矩阵、插件、云 Provider、诊断、打包、签名和企业级发布门禁。短时间内形成了大量跨层代码、重复 UIA 辅助函数、逐工作包文档和多套构建输出。

项目目录一度约 4.45 GB，而 Git 跟踪内容不足 2 MB。绝大多数磁盘占用来自 NuGet 缓存和重复构建产物；维护复杂度则来自范围过宽、每个小功能跨越过多层、以及日常提交重复执行正式发布级门禁。

用户明确选择保留轻量小产品理念，并批准“核心五项”方案。

## 决策

### 产品范围

当前只主动维护：

1. LauncherHost 任务栏入口；
2. WorkspacePanel 面板；
3. 基础响应式布局；
4. 本地便签；
5. 天气和手动位置设置。

计时器、待办、剪贴板、日历、系统监控、自动定位、云同步、账号、第三方插件和企业发布体系延期。

### 架构

- 保留已经验证的 LauncherHost、WorkspacePanel、CoreBroker、Client 和 Contracts 边界；
- 不增加 PluginHost、新进程或通用平台抽象；
- 已有卡片运行时和 Provider 调度进入维护状态；
- 新行为优先复用并简化现有链路；
- 对集中式大文件进行小步拆分，不做大爆炸重写。

### 工程门禁

采用 L0～L3 风险分级：

- L0 文档：diff 和链接检查；
- L1 纯逻辑：相关测试和必要的单项目构建；
- L2 UI/IPC/数据库：相关测试、一个 smoke、一个针对性真实流程；
- L3 发布候选：完整双配置、设备、无障碍、性能、安装和供应链矩阵。

L3 不再阻塞普通功能提交。

### 文档

- 不再为普通功能创建独立工作包；
- Git 保存详细历史；
- 状态页只保存当前事实、债务和下一步；
- ADR 只记录高成本、难回退的决策；
- 删除重复执行指南、旧调研和已完成工作包的当前副本。

### 生成物

- 删除可重建构建输出；
- 清理 NuGet HTTP 缓存和锁文件不再引用的旧版本；
- 保留当前锁文件需要的离线包；
- 隔离构建优先使用系统临时目录，结束后清理。

## 不变边界

本决策不降低：

- Explorer 无注入；
- 当前用户 IPC；
- 输入长度和版本验证；
- 数据库 revision、事务和恢复；
- 验收数据隔离；
- 无管理员、无默认遥测和隐私保护。

## 后果

正面：

- 当前路线和完成标准更清晰；
- 日常改动验证成本下降；
- 历史不再占据主要阅读上下文；
- 构建目录和缓存可控；
- 维护工作可以集中在核心五项和大文件拆分。

负面：

- 延期功能没有交付时间；
- 已实现的通用基础设施短期仍然偏重；
- 未来重新启用插件或云功能时需要新的范围和安全决策；
- 完整发布质量仍需在进入发布候选时集中验证。

## 替代关系

- 本 ADR 将产品需求 0.1 的完整 MVP 功能表替换为 0.2 轻量核心范围；
- 不废止 ADR-0001～0021 已经形成的数据和进程安全结论；
- ADR-0004 的插件安全方向保留为历史约束，但插件不在当前路线。
