# ADR-0010：便签仓储使用更新时间作为并发令牌

状态：Accepted
日期：2026-08-08

## 背景

NTE-001 要求便签输入后自动保存，并在保存失败或并发修改时避免静默覆盖。M2.1.1 已建立 `notes` 表，M2.1.2 已提供参数化访问和事务基础，但还没有领域仓储边界。

## 决策

- 在 CoreBroker 持久化层新增 `NoteRepository`，提供创建、读取、列表、搜索、更新和删除；
- 复用 schema v1 的 `notes` 表，不为本仓储新增迁移；
- 使用规范化 UTC `updated_at_utc` 作为乐观并发令牌，更新和删除必须带期望令牌；
- 令牌不匹配返回明确的 revision conflict，不覆盖另一份内容；记录不存在返回 not found；
- 便签正文只允许纯文本或基础 Markdown 字段，不进入剪贴板历史；
- UI 的防抖自动保存、撤销/复制交互和 IPC 映射不放入本仓储，分别由后续工作包实现。

## 后果

- 自动保存调用可以复用同一个 revision-safe update 边界；
- 不需要破坏性 schema 迁移，旧 M2.1.1 数据可直接使用；
- UI 仍需处理冲突提示、失败后的内存副本和重试；
- `updated_at_utc` 必须保持规范化格式，不能由调用方随意改写。
