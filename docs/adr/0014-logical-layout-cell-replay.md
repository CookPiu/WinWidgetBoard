# ADR-0014：持久化逻辑网格单元以恢复用户布局

状态：Accepted
日期：2026-08-08

## 背景

仅保存卡片顺序、跨度和 preferred column 时，程序重启或面板列数重新计算后只能重新执行 first-fit。用户主动留下的空位会被压缩，卡片的视觉位置也会随输入顺序变化；这会让保存后的布局看起来像恢复成默认布局。

## 决策

在布局项中增加可选的 `preferred row`，与 `preferred column` 组成逻辑网格单元：

- 拖动提交和完成编辑保存当前 placement 的行列；
- 加载布局时，若该逻辑单元格仍在当前列数范围内且没有冲突，优先恢复该单元格；
- 单元格因响应式列数变化不可用时，回退到既有的确定性 first-fit；
- 不保存绝对像素坐标，不改变 2/4/6 列响应式网格和尺寸跨度；
- 通过 SQLite schema v2 为旧数据库增加 nullable `preferred_row`，旧记录可继续读取。

## 理由

- 能区分“用户保存的空位”与“从未保存的默认排布”；
- 行列是 DPI、窗口宽度无关的逻辑数据；
- 旧布局仍可安全迁移，响应式列数变化仍有确定性降级路径；
- 保存仍只在完成编辑时发生，不把拖动帧写入数据库。

## 后果

正面：

- 重启后可恢复已保存的卡片相对位置和空位；
- 拖动后其他卡片不会因为重新 first-fit 而被隐式改写；
- 数据库迁移可回滚到迁移前备份。

限制：

- 列数改变导致单元格越界或冲突时，布局仍可能重新排布；
- 仍不支持任意像素定位和实时让位预览。

## 验证

- `UT-GRID-006` 验证含空位的逻辑单元格重放；
- `UT-LAYOUT-001`、`IT-LAYOUT-001` 验证 row 字段经仓储和 IPC 往返；
- schema v2 迁移测试验证旧 schema 迁移和备份边界；
- 真实桌面验收验证拖动、完成保存、关闭重开和第二轮编辑。
