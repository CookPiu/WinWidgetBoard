# ADR-0011：便签自动保存采用最新输入优先和内存草稿保留

状态：Accepted
日期：2026-08-08

## 背景

NTE-001 要求便签输入后自动保存，保存失败时不能丢失用户正在编辑的内容。M2.1.3 已交付 revision-safe 仓储，但 UI 还需要一个可取消、可测试的保存调度边界。

## 决策

- CoreBroker 持久化层提供单便签 `NoteAutosaveCoordinator`，由调用方提交草稿并等待结果；
- debounce 窗口内只保存最新草稿，旧任务以取消结束，不写入过期内容；
- 保存异常通过 `NoteAutosaveResult.Error` 返回，并保留 `InMemoryDraft`，不做无界自动重试；
- 关闭或取消时终止等待中的任务；服务不拥有 UI 可见性，也不直接显示告警；
- UI 后续负责把错误转换为提示、决定重试，并完成真实输入/失焦/关闭交互验收。

## 后果

- 自动保存调度可在无 UI、无 IPC 的单元测试中确定性验证；
- 失败时用户内容仍有内存副本，但进程崩溃前仍需要上层决定重试策略；
- 该服务只处理一个便签的最新草稿，多便签并行调度需由上层按实例管理。
