# ADR-0016：便签多项删除与编辑的安全边界

状态：Accepted
日期：2026-08-10
关联需求：NTE-001、NFR-REL-002、NFR-A11Y-002
关联工作包：M2.4.10

## 背景

M2.4.8 和 M2.4.9 已提供多便签列表、安全打开和新建能力。现有
`notes.delete` 已具备当前 revision 校验，但面板尚未提供删除入口。若只在
code-behind 直接调用客户端，容易遗漏未保存草稿保护、删除当前便签后的编辑器
状态和列表刷新边界。

## 决策

1. 继续复用已有 `notes.save`、`notes.get`、`notes.search` 和 `notes.delete`，不新增
   IPC 方法、数据库表或历史版本表。
2. 列表删除必须经过二次确认，并携带搜索结果中的 `UpdatedAtUtc`；当前便签删除
   使用编辑器内存中的最新 revision。revision 冲突或传输失败时保留原列表项和
   当前编辑内容。
3. 只有没有未保存草稿、没有进行中的保存/加载时才允许删除。列表项点击继续作为
   编辑入口，复用现有安全加载和自动保存。
4. 删除当前便签成功后，编辑器切换到空的 `primary-note` 草稿状态；刷新列表后，
   若仍有便签则打开列表第一项，避免继续显示已删除内容。
5. 本工作包不提供删除撤销或版本历史；不可逆删除必须由确认对话框明确告知。

## 后果

- 删除行为遵守现有 revision 并发保护，不会静默覆盖其他进程的修改；
- 用户可以从“全部”或搜索结果中继续打开便签编辑，也可以删除非当前便签；
- 删除当前便签后不会遗留已删除正文，空编辑器后续输入会按现有创建契约重新保存；
- 版本历史、删除撤销和回收站仍属于后续独立需求，不在本工作包中实现。
