# ADR-0023：入口改为嵌入任务栏条带的信息条

状态：Accepted
日期：2026-08-20
关系：扩展 [ADR-0001](0001-stable-taskbar-overlay.md)，不推翻其「不注入 Explorer」的结论

## 背景

ADR-0001 选定应用自有的 Win32 覆盖窗口作为入口，实现上把窗口放在工作区内、任务栏**上方**，形态是 52 DIP 的方形按钮。实际使用后提出两点：入口应当像原版小组件那样落在任务栏条带内、靠最左、有一定宽度；并且要能显示可切换的自定义信息。

真正进入任务栏仍然只有注入一条路，ADR-0001 已否决，`LCH-001` 也禁止进入 `explorer.exe`。因此可行的范围是：保持同一个覆盖窗口，把矩形从工作区移进任务栏条带。

## 决策

1. 新增 `ExactWidgetReplacement` 放置模式（枚举早已存在但从未产生），窗口矩形落在任务栏条带内，上下留边，高度夹在 32～40 DIP。
2. 条带由 `monitorRect` 减 `workArea` 在推断边上的差集推导，**不依赖 `ABM_GETTASKBARPOS`**——后者只返回主任务栏，副显示器无法获得。
3. 沿条带支持靠左、居中、靠右三种对齐，另保留原有悬浮形态；由用户选择。
4. 宽度随内容自适应，夹在 96～280 DIP 并按 4 DIP 量化；只有测量宽度跨过 8 DIP 滞回带才重排窗口。
5. 入口内容为可切换模式，当前实现日期与时间；天气模式另见「后果」。
6. 入口偏好（对齐、左对齐回退、显示内容）存放在 `HKCU\Software\WinWidgetBoard\Launcher`。
7. 仅读取用户级设置 `HKCU\...\Explorer\Advanced\TaskbarAl` 判断系统图标是否左对齐；值缺失即视为居中。不枚举 Explorer 子窗口，不读私有视觉树。

## 理由

- 形态变化被限制在放置算法与绘制，进程边界、IPC 和数据合同均未改动；
- 条带由工作区差集推导，对副显示器和非标准 DPI 更稳健；
- 偏好放注册表而非 CoreBroker：入口必须在连上 Broker 之前完成定位，且这是启动器本地视图设置，不是用户数据；
- 左对齐判断只用公开的用户设置，保持 ADR-0001 拒绝注入的立场。

## 放弃方案

- **注入 Explorer / XAML 视觉树**：ADR-0001 已否决，理由不变。
- **AppBar 独立停靠条**：会额外占用工作区，不是「任务栏内」。
- **靠枚举 Explorer 子窗口做精确避让**：Windows 11 任务栏是 XAML，子元素不是可枚举的 HWND，稳定判断需要私有接口。

## 后果

正面：

- 入口具备与原版小组件相近的观感与信息密度；
- 放置策略可由用户调整，不必为某一种任务栏配置写死。

负面与约束：

- **`IsRectWithin(workArea, …)` 这条安全网在嵌入模式下不再适用**，改由「必须落在条带内且落在显示器内」两条约束替代；两者都不满足时降级为悬浮。
- **topmost 层级是共享的**：另一个 topmost 的第三方任务栏扩展可能压在入口之上，直到启动器下一次 `EnsureTopmost` 重新声明。这是 ADR-0001 已记录的「第三方 Shell 冲突」在新形态下的具体表现，真实桌面回归必须先等待入口占据自身中心点再点击。
- 垂直任务栏（左/右边缘）无法容纳横向信息条，自动降级为悬浮。
- 任务栏自动隐藏时不嵌入，沿用原有降级路径。
- 系统图标左对齐时开始按钮占据最左，`靠左` 会按用户配置改为悬浮/居中/靠右，以继续满足 ADR-0001「系统按钮不被覆盖」的验证约束。
- 天气内容需要原生 Broker 请求，并且面板关闭时天气刷新目前按可见性暂停；让入口显示实时天气会与产品原则「按需运行」冲突，因此天气模式暂不开放，留待单独决定。
- 引入第二处持久化位置（注册表），CoreBroker 仍是唯一的用户数据存储。

## 验证

- `--geometry-smoke-test` 覆盖合成场景：三种对齐、条带内包含、宽度夹紧与量化、DPI 缩放、左对齐回退、自动隐藏/垂直/过薄条带降级；
- `scripts/Test-LauncherEntryPlacement.ps1` 覆盖真实桌面的条带内落位、宽高范围、入口外穿透与点击开面板；
- ADR-0001 的显示矩阵（多显示器、DPI、自动隐藏、Explorer 重启、全屏）仍然适用，未在本轮全部执行。
