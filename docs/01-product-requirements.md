# WinWidgetBoard 轻量产品需求

文档状态：已批准
版本：0.2
日期：2026-08-15
适用范围：轻量核心版

## 1. 产品定位

WinWidgetBoard 是一个 Windows 11 本地优先快捷工作台。用户通过独立任务栏按钮打开原生半屏面板，完成便签记录、天气查看和少量布局调整。

产品不替换 Windows Shell，不注入 Explorer，也不发展成新闻平台、插件市场或完整个人信息管理套件。

## 2. 产品原则

1. **少而稳定**：功能数量服从启动速度、后台占用和可靠性。
2. **本地优先**：便签和布局不依赖账号或云服务。
3. **公开 API**：任务栏入口只使用公开 Win32 能力。
4. **用户掌控**：无默认遥测、广告、新闻流或自动定位。
5. **按需运行**：面板关闭后停止不可见动画；后台只保留有界、低频且可测量的必要工作，当前仅天气按小时刷新以供任务栏入口显示（[ADR-0024](adr/0024-background-provider-keepalive.md)）。
6. **直接实现**：不为延期功能提前建立平台级抽象。

## 3. 当前核心范围

| 范围 | 需求编号 | 目标 |
| --- | --- | --- |
| 任务栏入口 | `LCH-001`～`LCH-004` | 安全显示、点击反馈、穿透和面板开关 |
| 工作台面板 | `PNL-001`～`PNL-005` | 原生面板、锚定开关、失焦/Esc 关闭 |
| 基础布局 | `LYT-001`～`LYT-006` | 响应式网格、编辑、拖动、保存和已有撤销 |
| 本地便签 | `NTE-001` | 创建、编辑、搜索、删除、Markdown 和自动保存 |
| 天气 | `WEA-001` | 当前天气、手动位置、刷新状态和来源说明 |

已经实现但不属于核心五项的演示卡片只作为布局占位，不继续增加业务行为。

## 4. 功能需求

### 4.1 系统

#### SYS-001 单实例

LauncherHost、WorkspacePanel 和 CoreBroker 各自保持单实例。重复启动应激活或连接现有实例。

#### SYS-002 普通用户运行

安装和基础运行不得要求管理员权限。

#### SYS-003 安全失败

无法确认任务栏位置、IPC 状态或数据状态时，应隐藏、降级或显示明确错误，不得覆盖系统控件或伪造成功。

### 4.2 任务栏入口

#### LCH-001 独立窗口

入口由应用拥有的 Win32 窗口实现，不进入 `explorer.exe`。

#### LCH-002 安全位置

默认嵌入任务栏条带并显示可切换信息，对齐方式由用户选择；条带由显示器与工作区矩形推导。
系统图标左对齐、任务栏自动隐藏、垂直任务栏或条带过薄时，按用户配置降级为悬浮位置或隐藏，
不覆盖开始按钮等系统控件。详见 [ADR-0023](adr/0023-embedded-taskbar-entry-strip.md)。

#### LCH-003 点击

鼠标按下立即反馈，释放时提交；拖出命中范围后释放取消。

#### LCH-004 命中与穿透

只有入口自身形状接收输入，其余区域穿透；高度不小于 32 逻辑像素，宽度随内容在 96～280 逻辑像素间自适应。

### 4.3 工作台面板

#### PNL-001 原生面板

使用独立 WinUI 3 顶层窗口，不显示普通任务栏按钮。

#### PNL-002 几何

面板保持在触发显示器工作区内，并受合理最小、最大宽度约束。

#### PNL-003 锚定开关

面板从入口方向展开，关闭沿相同路径返回；反向操作不得锁定输入。

#### PNL-004 关闭规则

入口切换、`Esc` 和面板外点击可以关闭；文本输入、拖动或模态对话框期间不得误关。

#### PNL-005 可恢复状态

Broker 不可用或数据加载失败时，面板仍能启动并显示可理解的不可用状态。

### 4.4 基础布局

#### LYT-001 响应式网格

按有效宽度使用 2/4/6 列逻辑网格，不保存绝对像素位置。

#### LYT-002 有限尺寸

继续支持现有 S/M/L/W/XL 离散尺寸，不新增自由像素布局。

#### LYT-003 显式编辑

普通模式禁止误拖；只有进入编辑模式后显示拖动和尺寸入口。

#### LYT-004 拖动

拖动保持抓取偏移、连续跟随、合法投影和 `Esc` 取消。

#### LYT-005 稳定排布

布局必须无重叠、无越界，并保持确定性。

#### LYT-006 保存

只在编辑完成时写入布局；保留现有 revision 保护和撤销能力，不继续扩展场景布局或复杂动效。

### 4.5 本地便签

#### NTE-001 便签

- 本地创建、编辑、列表、搜索和删除；
- 纯文本与基础 Markdown；
- debounce 自动保存；
- 保存失败保留当前草稿并允许重试；
- revision 冲突不静默覆盖；
- 不发展成知识库、协作编辑或版本管理系统。

### 4.6 天气

#### WEA-001 天气

- 使用 Open-Meteo 获取当前天气；
- 用户可以手动设置位置名称、纬度和经度；
- 默认不申请自动定位权限；
- 可见时按低频计划刷新，不可见时暂停非必要请求；
- 网络失败时显示状态并保留当前进程内同位置的最近成功数据；
- 显示数据来源；
- 当前不实现跨重启天气 payload 缓存。

### 4.7 最小设置

#### SET-001 设置入口

当前只要求天气位置及与核心五项直接相关的少量设置。取消不得产生外部副作用。

## 5. 非功能要求

### 5.1 性能

- 面板关闭后不持续等待 VSync；
- 不可见卡片停止纯 UI 动画；
- Provider 使用现有集中调度，不创建每卡永久定时器；
- 启动和后台占用以实际 Release 测量为准；
- 60 MB 后台工作集和 300 ms 可交互仍是方向目标，但只在发布候选阶段作为正式门禁。

### 5.2 可靠性

- 用户内容写入使用事务或 revision 保护；
- IPC 断开可以重连；
- 单卡或天气失败不阻止便签和布局使用；
- 不允许无界队列、无限重试或无限日志。

### 5.3 安全与隐私

- IPC 只允许当前用户；
- 会话令牌不得写日志；
- 便签正文不得进入诊断日志；
- 天气请求只发送用户选择的位置和必要字段；
- 默认无账号、遥测和自动定位。

### 5.4 无障碍

核心流程需要键盘可达、明确焦点、UIA 名称、减少动态效果和高对比度基础支持。完整设备与偏好矩阵仅在发布候选阶段执行。

## 6. 核心验收

日常开发只维护以下核心旅程：

1. 入口点击可以打开和关闭面板；
2. 面板在一个明确的 Windows 11 x64 参考环境中正确显示；
3. 四卡布局可拖动、保存并在重启后恢复；
4. 便签可创建、保存、搜索、打开和删除；
5. 天气可加载，位置可修改并在 Broker 重启后恢复；
6. 验收实例和数据库与生产数据隔离。

多显示器、完整 DPI、高对比度、屏幕阅读器、性能、长稳、安装和签名矩阵属于发布候选验证，不再阻塞每个功能提交。

## 7. 延期范围

以下内容不在当前路线中：

- 计时器业务；
- 本地待办；
- 剪贴板卡片；
- 本地或云日历；
- 系统监控和高级硬件；
- 自动定位；
- Outlook、Google、Microsoft To Do；
- 第三方插件、PluginHost、插件 SDK 和市场；
- 云同步、账号、遥测平台；
- 多套布局、自由像素布局；
- 企业级安装、更新通道和管理策略。

重新启用任何延期范围前，必须由用户明确选择，并先评估对体积、后台资源和维护成本的影响。

## 8. 成功标准

轻量核心版成功不以功能数量衡量，而以以下结果衡量：

- 核心五项日常可用；
- 启动和后台占用保持克制；
- 代码可以由少量维护者理解和修改；
- 普通改动不需要跨越大量无关文件；
- 项目目录不长期积累可重建输出；
- 用户数据和隐私边界保持可靠。
